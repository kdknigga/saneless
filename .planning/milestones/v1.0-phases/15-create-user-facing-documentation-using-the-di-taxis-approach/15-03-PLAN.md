**docs/reference/web-api.md** (per D-08 item 4, D-12 terse style):
- Title: `# Web API`
- Intro: saneless exposes a web API at the configured host:port. The web UI uses these endpoints via HTMX. They can also be called directly for integration.
- Endpoint table (overview):
  | Method | Endpoint | Purpose |
  |--------|----------|---------|
  | GET | `/` | Web UI main page |
  | GET | `/health` | Health check (no auth) |
  | GET | `/api/paperless/test` | Test paperless connection |
  | POST | `/api/scan` | Start a scan job |
  | GET | `/api/jobs/current/status` | Poll current job status |
  | GET | `/api/tags` | Fetch paperless tags |
  | GET | `/api/correspondents` | Fetch paperless correspondents |
  | POST | `/api/cache/invalidate` | Refresh cached data |
  | GET | `/api/jobs/history` | Job history |
  | POST | `/api/flip/continue` | Continue manual duplex scan |
  | POST | `/api/flip/abort` | Abort manual duplex scan |

- Detailed section for key endpoints:

  ### `GET /health`
  Returns 200 when system is healthy, 503 when worker thread is down.
  No authentication required.
  Response: `{"status": "ok"}` (200) or `{"status": "unhealthy", "detail": "..."}` (503)

  ### `GET /api/paperless/test`
  Tests connection to configured paperless-ngx instance.
  Response: `{"status": "connected"}` (200), `{"status": "token_rejected"}` (401), `{"status": "unreachable"}` (502)

  ### `POST /api/scan`
  Starts a scan job. Accepts form data (HTMX form submission).
  Fields: `profile` (string), `title` (string), `tags` (int[], optional), `correspondent` (int, optional)
  Response: HTML partial (HTMX) showing scan status

  ### `GET /api/jobs/current/status`
  Returns current job status as HTML partial for HTMX polling.
  States: IDLE, SCANNING, ASSEMBLING, UPLOADING, DONE, ERROR, AWAITING_FLIP

  ### `POST /api/flip/continue` and `POST /api/flip/abort`
  Manual duplex flow controls. Continue resumes scanning backs; abort cancels the job.

- Note: Most endpoints return HTML partials (designed for HTMX). The `/health` and `/api/paperless/test` endpoints return JSON.

**docs/reference/docker.md** (per D-08 item 5, D-12 terse style):
- Title: `# Docker`
- Image: `ghcr.io/kris-knigga/saneless:latest`
- Base image: `python:3.14-slim`
- Entrypoint: `saneless serve`
- Port: `8080` (configurable via `SANELESS_OUTPUT__WEB_PORT`)
- Healthcheck: `curl -f http://localhost:8080/health` (30s interval, 5s timeout, 3 retries, 30s start period)

  ## Volumes
  | Mount Point | Purpose | Required |
  |-------------|---------|----------|
  | `/etc/saneless/config.toml` | Configuration file (read-only) | Yes |
  | `/tmp/saneless` | Scan temp files and SQLite DB | No (ephemeral OK) |
  | `/consume` | Consume directory fallback | No (only if using fallback) |

  ## Environment Variables
  All `SANELESS_*` env vars are supported. Common ones for Docker:
  | Variable | Typical Value | Purpose |
  |----------|---------------|---------|
  | `SANELESS_SCANNER__HOST` | `192.168.1.50` | Network scanner IP |
  | `SANELESS_PAPERLESS__URL` | `http://paperless:8000` | Paperless URL (Docker network) |
  | `SANELESS_PAPERLESS__TOKEN` | `abc123def456` | API token |

  ## Minimal docker-compose.yml
  ```yaml
  services:
    saneless:
      image: ghcr.io/kris-knigga/saneless:latest
      ports:
        - "8080:8080"
      volumes:
        - ./config.toml:/etc/saneless/config.toml:ro
  ```

  ## USB Scanner Access
  For USB-connected scanners, pass the device:
  ```yaml
  devices:
    - /dev/bus/usb:/dev/bus/usb
  ```
  Note: This is NOT required for network scanners (use `SANELESS_SCANNER__HOST` instead).

  ## Network Scanner Access
  See [Scanner Host Discovery](../how-to/scanner-host-discovery.md) for detailed setup.
