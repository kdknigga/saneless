  <action>
When `filterwarnings = ["error"]` is enabled, `ResourceWarning: unclosed database in <sqlite3.Connection>` becomes a test failure. Fix all test files that create JobStore instances without closing them.

**Step 1: Identify the problem.** Run `uv run pytest -W error 2>&1 | head -100` to see which tests fail with ResourceWarning. The RESEARCH.md identifies: test_pipeline, test_web, test_worker, test_job, test_cli.

**Step 2: Fix unclosed connections.** For each affected file, ensure every `JobStore()` instance gets `.close()` called. Two approaches:

Approach A (preferred for fixtures): Create a yield fixture in conftest.py that provides a JobStore and closes it on teardown:
```python
@pytest.fixture
def job_store(tmp_path: Path) -> Iterator[JobStore]:
    """Provide a JobStore with automatic cleanup."""
    store = JobStore(db_path=str(tmp_path / "test.db"))
    yield store
    store.close()
```

Approach B (for inline creation): Wrap in try/finally or use contextmanager pattern where JobStore is created inline in tests.

**Step 3: Audit every test file.** Search for `JobStore(` in each file and ensure each instance is closed:
- test_job.py: Some tests already have try/finally with store.close() but `test_list_recent`, `test_prune_old_jobs`, etc. at the top may not.
- test_pipeline.py: Check if pipeline tests create JobStore instances directly.
- test_web.py: TestClient lifespan may create JobStore via app factory.
- test_worker.py: Worker tests create JobStore for the worker.
- test_cli.py: CLI invocation may create JobStore.

**Step 4: Verify.** Run `uv run pytest -W error` and confirm zero ResourceWarning failures. Also handle any other warnings that surface (DeprecationWarning, etc.) -- per CONTEXT.md decision, zero allowlisting.

All type annotations and docstrings on new/modified code must follow the standards established in Plan 02.
