## Critical Gaps

### GAP-01: No `saneless serve` command (blocks web UI deployment)

**Severity:** Critical
**Affected requirements:** UI-01–08, PROF-03, PLSS-04, PLSS-05, HLTH-01, HLTH-02, LOG-03, PKG-02

`create_app()` in `src/saneless/web/app.py` is fully implemented and tested. Routes, templates, worker integration, cache — all wired and passing tests via `TestClient`. However, no CLI command exists to start the web server at runtime. The CLI defines only `scan`, `devices`, and `jobs` commands.

`OutputConfig.web_host` and `OutputConfig.web_port` are defined in `config.py` but never read by any code path.

`uvicorn` is listed as a production dependency but never imported or invoked.

**Fix:** Add `saneless serve` command calling `uvicorn.run(create_app(...), host=settings.output.web_host, port=settings.output.web_port)`. Update Dockerfile with `CMD ["serve"]`.

### GAP-02: PLSS-03 web route missing

**Severity:** Medium
**Affected requirements:** PLSS-03

`PaperlessClient.test_connection()` exists at `paperless.py:205` and correctly returns `"connected"`, `"token_rejected"`, or `"unreachable"`. However, no `GET /api/paperless/test` route handler exists in `routes.py`.

**Fix:** Add route handler in `routes.py` calling `state.paperless.test_connection()`.

### GAP-03: Worker skips ASSEMBLING/UPLOADING states

**Severity:** Low
**Affected requirements:** UI-02 (partial)

The pipeline's status callback prints "Assembling PDF..." and "Uploading to paperless-ngx..." to the CLI, but the worker never calls `job_store.update_state(job_id, JobState.ASSEMBLING)` or `JobState.UPLOADING`. The web UI status area will jump from SCANNING directly to DONE.

**Fix:** Add `update_state` calls in worker before PDF assembly and upload steps.

## Broken E2E Flows

### Flow 2: Container deployment — BROKEN
