<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| GitHub Actions runner → repository | A workflow's `GITHUB_TOKEN` can mutate the repo if over-privileged |
| Third-party action → runner | Action code executes with full runner privileges and sees the token |
| PyPI → developer machine and runner | `uv add` pulls executable package code into the venv |
| Untrusted PR head → runner | Any fork/branch PR triggers `pull_request` and runs this workflow |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-01 | Elevation of Privilege | `ci.yml` `GITHUB_TOKEN` scope | mitigate | Workflow-level `permissions: { contents: read }`; no job escalates. Verified by grep in Task 2 acceptance criteria |
| T-20-02 | Tampering | `actions/checkout`, `astral-sh/setup-uv` supply chain | mitigate | Full 40-hex SHA pins with version comments, plus `.github/dependabot.yml` in the same commit so the pins are maintained rather than frozen (D-18) |
| T-20-03 | Denial of Service | Hung test consuming the CI job budget | mitigate | `pytest-timeout` `timeout = 60` in `pyproject.toml` (fires locally and in CI identically) plus `timeout-minutes` on both jobs, which also bounds apt and `uv sync` |
| T-20-04 | Tampering | `pytest-timeout` package legitimacy | mitigate | RESEARCH.md § Package Legitimacy Audit: `pytest-timeout` 2.4.0, pytest-dev org, `slopcheck` `[OK]`, disposition Approved. No `[ASSUMED]`/`[SUS]`/`[SLOP]` packages in this phase, so no blocking legitimacy checkpoint is required |
| T-20-05 | Information Disclosure | Workflow logs from a `pull_request` run | accept | `pull_request` (not `pull_request_target`) runs with a read-only token and no secrets are referenced by `ci.yml`; nothing sensitive can be echoed |
| T-20-SC | Tampering | `uv add --dev` install step | mitigate | Covered by T-20-04; audit table present and clean, so installs proceed without a human legitimacy gate |
</threat_model>
