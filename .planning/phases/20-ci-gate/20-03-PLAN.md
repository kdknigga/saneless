    obvious cause. Read them; do not infer them.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local history → remote repository | The first push is effectively irreversible |
| Pull request head → GitHub Actions runner | PR head code executes in CI |
| `gh` token → repository refs | Push and PR creation are write operations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-11 | Information Disclosure | Published git history | mitigate | Re-verified after push: `.planning/` count 0 on both pushed refs and across every commit between them; repo confirmed private again before the push |
| T-20-12 | Tampering | Accidental advance of `master` | mitigate | No merge and no `<branch>:master` push permitted (D-21); acceptance criteria assert `origin/master` still points at the original root commit |
| T-20-13 | Elevation of Privilege | A weakened gate used to force a green run | mitigate | Explicit prohibition on `continue-on-error` / `|| true` / removed steps; the green run's log is asserted to contain all five check commands |
| T-20-14 | Spoofing | A status check named `lint`/`test` posted by a non-Actions app satisfying the future rule | mitigate | The app id is read back here and pinned via `integration_id` in Plan 04's ruleset |
| T-20-15 | Information Disclosure | PR title/body leaking the planning trail | mitigate | PR body must not cite `.planning/` paths or the internal code review |
</threat_model>
