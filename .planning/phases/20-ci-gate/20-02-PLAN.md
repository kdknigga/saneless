<objective>
Do everything that must happen BEFORE the repository is published, and stop at a blocking
checkpoint. Three things: switch `kdknigga/scanless` to private (D-23), re-verify no secrets are
about to be published (D-24), and build the `.planning/`-stripped branch locally without pushing it
(D-22).

Purpose: the remote is empty and public. Once a push lands, both the visibility decision and the
history are irreversible in practice. This plan front-loads every reversible step and puts the
point of no return behind an explicit human approval.

Output: a private repo, a verified-clean local branch, and a recorded user approval that authorizes
Plans 03 and 04 to push, open a pull request, and apply the ruleset.

This plan modifies no files in the working tree. Its effects are one GitHub repo setting and one
local git ref.
</objective>

    `uvx git-filter-repo --path .planning --invert-paths --force`. `git-filter-repo` is NOT installed
    and must NOT be permanently installed — `uvx` runs it ephemerally (confirmed available).

    (`git fetch <scratch> <branch>:<PR_BRANCH>`) so Plan 03 can push it from here. `master` is a single
    root commit with no `.planning/` in its tree, so it is unaffected and remains the PR base.

    Delete the scratch clone when done.

    If filter-repo fails or produces an implausible result, STOP and surface it at the Task 3
    checkpoint. **Do not fall back to squashing** — D-25 explicitly rejected publishing a
    single-commit history, and that choice is the user's to revisit, not the executor's.

    Confirm `ci.yml` and `dependabot.yml` from Plan 01 are present in the branch head — without them
    the pull request in Plan 03 has no workflow to trigger.

    **Do not push. Do not create a pull request.** Leave `autodev` checked out and unmodified when done.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Local git history → public internet | The first push publishes 337 commits of history that has never been reviewed for disclosure |
| Local `gh` token → repo settings | A visibility change and, later, a ruleset write are admin-scope mutations |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-20-06 | Information Disclosure | First publication of repo history while the repo is PUBLIC | mitigate | Visibility set to private and read back as `true` before any push (D-23); Task 1 hard-stops if the remote already has refs |
| T-20-07 | Information Disclosure | `.planning/` (code review, research, debug notes) reaching the remote | mitigate | Full `.planning/` strip verified per-commit, not just on the head tree, so no blob is published in history (D-22) |
| T-20-08 | Information Disclosure | Credentials embedded in tracked files | mitigate | Fresh regex sweep over `git ls-files` for token-shaped strings, plus confirmation that `saneless.toml` is untracked and `site/` is not committed (D-24) |
| T-20-09 | Repudiation | An irreversible publication performed without the user's knowledge | mitigate | Blocking human checkpoint enumerating exactly what will be pushed, before any push |
| T-20-10 | Elevation of Privilege | `gh` token used for an admin-scope visibility change | accept | The token is the user's own OAuth token with `repo` scope and `admin: true` on this repo; the action is scoped to one setting on one repo and is reversible |
</threat_model>
