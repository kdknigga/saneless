<objective>
Two hygiene defects the deep review found in code this phase wrote or reworked: a generated
document title that can carry a trailing space, and a log line that interpolates a user-supplied
title without escaping it.

Purpose: IN-06 is a real artefact leaving the appliance -- `LOCAL_TIME_FORMAT` ends in `%Z`, which
`strftime` renders as the empty string when the platform reports no zone abbreviation, and
`resolve_job_title` interpolates the result straight into `f"Scan {local_time(now)}"`, so such a
host files a paperless-ngx document whose title ends in a space. IN-03 is the log-forging discipline
`web/errors.py`'s module docstring already states -- request input goes into a log line with `%r`
"so a control character in them is escaped and cannot forge a log line" -- applied to the one new
call site this phase added and the two older ones it now sits beside.
Output: a `local_time` that cannot emit trailing whitespace, and three `%r` conversions.
</objective>
