<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config file (including the token) -> terminal output | `doctor` reads secrets and prints a report |
| paperless-ngx / scanner host -> doctor output | Remote responses influence what is printed |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-31 | Information disclosure | `doctor` printing check rows | mitigate | Every message and next step comes from `checks.py`, whose guard test already forbids paths, URLs, token values and exception text (plan 30-06). `doctor` adds only the bracket token and the padded name |
| T-30-32 | Information disclosure | `_load_cli_settings` logging | accept | Existing behaviour, unchanged: `log_config_sources` already runs for every command and the token is a `SecretStr` masked in repr and `model_dump` (CFG-05, N-15) |
| T-30-33 | Spoofing (scripted health gate) | a `WARN` silently failing or passing a gate | mitigate | D-01's mapping is explicit, tested per state, and documented in an `**Exit codes:**` table that a doc-truth test hard-fails on if it disappears |
| T-30-34 | Denial of service | `doctor` hanging on an unreachable host | mitigate | It calls the same bounded registry the strip does: a socket pre-probe before SANE and a bounded `httpx.Timeout` for Paperless (plan 30-06) |
| T-30-35 | Denial of service | a container HEALTHCHECK calling `doctor` | mitigate | Out of Scope in REQUIREMENTS; the new reference section states the reason in prose so an operator does not wire it up |
| T-30-SC | Tampering | npm/pip/cargo installs | accept | This plan installs nothing |
</threat_model>
