<objective>
Stop the host parser raising, and stop it handing the probe addresses glibc invents.

Purpose (R3-CR-01): the port branch gates `int(maybe_port)` on `maybe_port.isdigit()`, and
`str.isdigit()` is `True` for Unicode category `No` characters -- `²` (U+00B2), `①` (U+2460) --
for which `int()` raises `ValueError`. `_saned_hosts` catches nothing, `_scanner_preflight` catches
nothing, and the probe's `except OSError` is never reached because the raise happens before any
socket call. The exception escapes into `run_checks`' generic per-check handler, which renders
"This check could not be completed." and a FAIL Scanner row; `worst_state` is then FAIL and
`saneless doctor` exits `ExitCode.CONFIG` (2) on an appliance whose scanner works. It is reachable
from the environment, not only the config file: `_saned_host_setting` prefers `SANE_NET_HOSTS`.
The same gate accepts `'٦٥٦٦'` (Arabic-Indic) as port 6566, a number libsane's own parsing would
never derive from that string -- which is the exact divergence `_saned_host_setting` exists to
prevent.

Purpose (R3-WR-01): `_looks_like_a_host_name` rejects a segment only when `segment.isdigit()`, but
the hazard it was written for is glibc's non-dotted-quad numeric parsing, which accepts far more
than all-digit strings. Measured by round 3 on this machine: `0.0` and `0x0.0` resolve to
`0.0.0.0`, `0x7f.1` and `127.1` resolve to `127.0.0.1`, and all four pass the current guard because
they contain a `.`. A `connect()` to `0.0.0.0` on Linux reaches loopback, so any unrelated local
process listening on 6566 makes `any(...)` true, suppresses `_scanner_host_unanswered`, and lets
the check fall through to `get_devices()` -- reinstating the ~127 s uninterruptible hang the
pre-probe exists to avoid. And the parser can still *invent* such a segment from a typo:
`_saned_hosts("host:0.0")` returns `(("host", 6566), ("0.0", 6566))`, so a stray `.` in a port
dials `0.0.0.0`.

Purpose (R3-IN-05): `_saned_hosts` puts no cap on the number of entries, and `_scanner_preflight`
walks them with `any(...)`, paying an unbounded `getaddrinfo` plus `PROBE_CONNECT_SECONDS` for
each. That walk runs inside the `POST /api/checks/refresh` request thread, so a 40-host setting is
a request that can take minutes. The scanner gate is free throughout (R2-IN-03's fix), so no scan
is parked -- but the manual-refresh floor bounds rate, not duration.

Purpose (R3-IN-04): three documented behaviours of `_saned_hosts` diverge from what it does. The
docstring is the contract the next maintainer reads; each of the three is corrected and pinned.

Output: a port branch that is ASCII-decimal only, a segment filter that refuses every numeric form
glibc reads as an address while still accepting a legal dotted quad, a bounded dial list, and a
docstring with a test behind every sentence.

## Out of scope

Nothing about the probe's own budget, deadline walk or gate boundary changes here. The 2 s saned

`decision_record` settled them; "bound the enumeration with a worker thread plus a deadline" was

<decision_record>
## What `_saned_hosts("host:²")` returns, and why it is not `()`

`30-VERIFICATION.md`'s `missing:` entry asks for a test pinning `_saned_hosts('host:²') == ()`.
This plan pins `_saned_hosts("host:²") == (("host", SANED_PORT),)` instead, deliberately.

Once the port branch's condition is false, control falls through to the final filtered return,
which keeps every segment that could be a host name. That is exactly the reading this module
already gives an out-of-range port: the docstring states, and `tests/test_checks.py` already pins,
that `host:99999` yields `host` alone. Returning `()` for `host:²` would mean an unparseable port
refuses the whole setting in one spelling and keeps the host in another -- two readings of the
same defect class, one of them undocumented.

**Rejected: refuse the whole setting when the port segment is unparseable.** It would make
`host:99999` and `host:²` agree only by also changing `host:99999`, which is a behaviour change
to a pinned, documented case with no defect behind it, in a plan whose job is to stop a crash.

The property the gap is actually about is pinned either way and is pinned here explicitly:
`_saned_hosts` does not raise on a Unicode-digit port, the Scanner row is not the generic
"This check could not be completed." row, and `worst_state` is not FAIL. The dialled port in the
fallback is `SANED_PORT`, which is the default sane-net itself uses -- not an address nobody
configured.

## The root-dot case (R3-IN-04, third item)

`_saned_hosts("scanner.local.")` returns `()`, because the trailing-dot rule rejects a legal
fully-qualified name written with its root dot. This plan **corrects the docstring and pins the
behaviour with a test**; it does not start accepting the root dot. Widening the accept surface for
a spelling that appears nowhere in this project's config examples buys nothing, and the cost of the
current behaviour is only the pre-probe's latency saving -- the safe direction the whole module is
built on.
</decision_record>
