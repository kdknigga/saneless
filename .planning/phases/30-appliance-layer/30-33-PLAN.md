<objective>
Stop one surprise from silently ending the appliance's background health checks for the life of
the process.

Purpose: `CheckRefresher._run` is `while not self._stopping.wait(TICK_SECONDS): self._tick()`,
with no `try`. `ScanWorker._run` (`worker.py:1076-1101`) wraps each iteration in
`try`/`except Exception` precisely so that "nothing ends the loop but stopping (ROBU-01)", and
`CheckRefresher`'s own class docstring claims it "follows `ScanWorker` in every structural respect
D-07 names" -- it does not follow this one.

There is a live path to a raise. In `_probe_and_store` the store sits in the `else` arm of the
`try`, and Python does not route an exception raised in `else` to that `try`'s handlers, so a raise
from `self._cache.store(results)` propagates out of `_probe_and_store`, out of `_tick`, and ends
`_run`. The consequence is the one `POLL_ATTEMPT_CAP`'s own comment names as its motivating case:
"an appliance whose refresher thread has died". The cache then never updates again, silently, for
the life of the process, and the strip's only remaining source of results is the `Check again`
button. The same raise out of `probe_now()` also 500s `POST /api/checks/refresh` with the manual
claim already spent.

Output: both halves of the fix -- the store moved inside the guarded region, and a per-tick
backstop in the loop -- each with a test that fails without it.

## Out of scope

Nothing about *when* the refresher probes changes: the two guards in `_tick` (nobody watching,
cache still fresh), the TTL, the single-flight lock, `probe_in_flight`'s `locked()` read and
`probe_now`'s "did I probe" contract are all left exactly as plans 30-25, 30-26 and 30-29 left
them. The compare-and-clear hardening of the manual-refresh claim is R3-IN-03 and belongs to plan
30-36.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| background thread -> cache | the refresher is the only writer of the strip's results; if it dies the page silently shows stale data with a fresh-looking timestamp |
| `POST /api/checks/refresh` -> `probe_now` | an unauthenticated LAN request reaches this code path directly, so an exception here is an exception in a request thread |
| exception -> log | the exception text goes to the log and must not reach the cache or the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-33-01 | Denial of Service | `CheckRefresher._run` | mitigate | per-tick `try`/`except Exception` with `logger.exception`, mirroring `ScanWorker._run`, so no single surprise ends the appliance's background health checks for the life of the process (task 2) |
| T-30-33-02 | Denial of Service | `_probe_and_store`'s `else` arm | mitigate | the store moves inside the guarded region, so a raising store neither kills the thread nor 500s the refresh endpoint with the manual claim spent (task 1) |
| T-30-33-03 | Information Disclosure | the logged exception | accept | `logger.exception` is the established channel for this module and the existing `except` arm already uses it; nothing from the exception reaches the cache, the strip or the JSON error shape (ASVS V7 unchanged) |
| T-30-33-04 | Repudiation | a swallowed tick failure | mitigate | every swallowed failure is logged once at exception level, so a silently-degrading appliance leaves a trace in `docker logs` rather than none |
| T-30-33-SC | Tampering | npm/pip/cargo installs | accept | this plan installs no packages |
</threat_model>
