<objective>
Give the profile-default fallback the one fact it was missing -- whether the control was on the
page at all -- and stop the index page paying for metadata it will not render.

Purpose: WR-06 is a behaviour regression, not just an unimplementable intent. `tags = tags or
found.default_tags` cannot tell "the control was not rendered" from "the control was rendered and
the user cleared it"; both arrive as an empty list. With the default `show_tags = true` and a
profile carrying `default_tags`, a household member who unticks every box silently gets the
profile's tags applied anyway. Before this phase the web path applied no profile defaults at all,
so this is something the appliance used to be able to do and now cannot. D-29's stated intent --
"with `show_tags` off, the submit carries nothing for that field and the profile's own default is
what applies" -- names the setting explicitly, and the setting is exactly the fact that
distinguishes the two cases.
Output: a fallback gated on the config key, two guarded metadata fetches, and the file's last ASVS
V7 outlier.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN browser → `POST /api/scan` | untrusted form input decides what is filed |
| server → server log file | exception text from a Paperless client may carry credentials |
| server → paperless-ngx | each metadata fetch is an outbound request an anonymous page load can cause |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-23-01 | Information disclosure | `paperless_test` log line | mitigate | Log `type(exc).__name__`; a `user:pass@` URL inside an `httpx` exception string can no longer reach the log. Pinned behaviourally and by a source guard so a later handler cannot reintroduce it. |
| T-30-23-02 | Tampering | profile defaults applied to a submit | mitigate | The fallback is gated on a server-side config key, never on anything the request carries, so a crafted submit cannot choose whether the profile's defaults apply. A submit that names tags still keeps them. |
| T-30-23-03 | Denial of service | anonymous page loads causing paperless-ngx traffic | mitigate | With the optional controls off, a cold-cache page load now issues zero metadata requests, removing two outbound round-trips per load from an unauthenticated surface. The remaining fetches stay behind `MetadataCache`'s TTL. |
| T-30-23-04 | Spoofing | `show_tags` / `show_correspondent` as a security control | accept | These are form-shape settings, not authorisation. The route still accepts a `tags` field when the control is off; it is simply overridden by the profile's defaults. REQUIREMENTS already states the appliance has no authentication on the LAN. |
| T-30-23-SC | Tampering | npm/pip/cargo installs | n/a | No package is installed; `pyproject.toml` is untouched. |
