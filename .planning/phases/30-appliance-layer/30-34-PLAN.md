<objective>
Make the flag both surfaces are documented to render actually render.

Purpose: `grep -rn skipped src/saneless/web/templates src/saneless/cli.py` returns nothing.
`check_row` takes `(name, state_class, glyph, state_label, message, next_step)` and `doctor` prints
`_state_marker(result.state)`; neither reads `CheckResult.skipped`. Both skipped rows therefore
render as a green tick with the screen-reader word "OK" in front of a sentence that says nothing
was checked -- "OK Scanner  The scanner was busy, so it was not checked this time." and
"OK Scanner  Not checked while a scan is running." `_scanner_skipped`'s docstring says "The
`skipped` flag, **not the state**, is what the two surfaces render" and `_scanner_busy`'s says
"The `skipped` flag discloses that nothing was checked"; both are false as shipped.

This is a correctness problem and not only a comment problem. The neutral cold-start trio
(`CHECKING_GLYPH`, `CHECKING_STATE_CLASS`, `CHECKING_STATE_LABEL`) already exists for exactly "we
did not look" and is already used by `_CheckingRow`; a green tick claiming OK for an unprobed row
is the same lie-by-marker this phase rejects everywhere else, and it directly undermines the phase
goal of telling a household member at a glance whether the appliance is healthy.

Output: three row-level filters keyed on the flag, a macro that takes it, a doctor marker that
shows it, tests on both surfaces, and two docstrings that are true.

## Out of scope

The `CheckState` enum gains no fourth member. "We did not look" stays a flag rather than a state,
for the reason `CheckResult`'s own docstring gives -- the row still needs *some* state for its
colour, and a fourth state would owe `saneless doctor` an exit-code rule (D-01). The skipped row's
message wording is UI-SPEC S1's and is not changed here.
</objective>

<decision_record>
## The screen-reader word for a skipped row is "Not checked", not "Checking"

The glyph and the colour class are reused from the cold-start trio, exactly as R3-WR-03 proposes:
`CHECKING_GLYPH` (U+00B7, neutral -- it says "not yet", not "bad") and `CHECKING_STATE_CLASS`.
No new colour token is needed and none is added.

The **word** is not reused. `CHECKING_STATE_LABEL` is "Checking", and a listener hearing
"Checking: Scanner. The scanner was busy, so it was not checked this time." is told a probe is
running when none is -- a smaller version of the same lie the green tick tells. A new constant
`SKIPPED_STATE_LABEL = "Not checked"` costs one line and one export, and it is the only way the
glyph's meaning survives as speech, which is the reason `CHECKING_STATE_LABEL` exists at all.

## `saneless doctor` gets the marker even though it cannot currently produce a skipped row

`doctor` builds its `CheckContext` with `skip_scanner` left at its default and passes no scanner
gate, so neither `_scanner_skipped` nor `_scanner_busy` is reachable from the CLI today -- round 3
and the verifier both say so. The marker is still wired, for two reasons: D-02's whole claim is
that one registry feeds both surfaces, and a surface that would mis-render a row the registry can
produce is a latent divergence waiting for the first caller that passes `skip_scanner=True`; and
leaving `skipped` half-wired is what produced this finding in the first place.

Because it is unreachable today, it is tested at the seam (`_row_marker` directly) and through a
`run_checks` stub, and `cli.py` carries a comment saying plainly that no current invocation
produces this marker and why it exists anyway -- so the next reviewer reads the reason instead of
filing it as dead code.
</decision_record>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| check registry -> rendered row | the row is the appliance's only health signal to a non-technical reader; a marker that overstates health is a security-relevant misreport, not only a cosmetic one |
| check registry -> `doctor` exit code | a scripted health gate keys on the exit code (D-01) |
| Python constants -> template | the template must render no word it authors itself |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-34-01 | Spoofing | `check_row` macro | mitigate | a row nobody probed renders the neutral marker and the words "Not checked", so the strip cannot claim a verified-healthy scanner it never looked at (task 1, task 2) |
| T-30-34-02 | Repudiation | `saneless doctor` output | mitigate | `_row_marker` prints `[SKIP]` for an unprobed row, so a captured `doctor` transcript records what was actually checked (task 3) |
| T-30-34-03 | Denial of Service | `doctor` exit code | accept | the state stays `CheckState.OK` for a skipped row by design, so this change cannot turn a running scan into a red health gate; the exit-code rule is untouched and pinned by a test |
| T-30-34-04 | Information Disclosure | the new label and marker | accept | both are developer-authored constants with no host, path, URL or exception text (ASVS V7) |
| T-30-34-SC | Tampering | npm/pip/cargo installs | accept | this plan installs no packages |
</threat_model>
