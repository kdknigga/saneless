<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| query parameter `q` -> cached tag list | Free-form client input drives a server-side filter |
| query parameter `tags` -> rendered checked state | Client-supplied ids decide which boxes are pre-checked |
| paperless-ngx tag names -> rendered HTML | Upstream-controlled text crosses into the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-74 | Tampering (reflected XSS) | `q` echoed into the tag list | mitigate | `q` is never rendered: it is a filter, not a label, and a template grep asserts `{{ q }}` does not appear. Jinja autoescape covers the tag names that are rendered |
| T-30-75 | Tampering (SSRF / injection) | `q` reaching paperless-ngx | mitigate | The filter is a Python-side `in` over the already-cached `MetadataCache` list; a request-counting `MockTransport` test asserts a warm-cache filter issues zero upstream requests and that no request carries `q` (ASVS V5) |
| T-30-76 | Denial of service | an unbounded `q` | mitigate | `Query(max_length=...)` rejects an over-long value with 422 before any filtering, at the boundary, matching the `MetadataResource` precedent |
| T-30-77 | Tampering (data loss) | a filter swap silently dropping a ticked tag | mitigate | A-5: `hx-include="#tags-list"` carries the current selection, the route re-renders it checked and pins filter-excluded selections above the list; a test ticks two tags, filters one out and asserts both submit |
| T-30-78 | Spoofing (UI) | Enter in the filter starting a scan | mitigate | A-6: the input's HTML form owner is `#tag-filter-form`, so implicit submission goes there; a stray-`q` POST regression test covers the residual case |
| T-30-79 | Tampering (config bypass) | hiding a control with CSS | mitigate | The controls are absent from the rendered markup; tests assert absence of the ids and that no `display: none` achieves it |
| T-30-80 | Spoofing (behaviour) | a hidden control silently changing what a scan does | mitigate | D-29: two regression tests assert the profile's `default_tags` and `default_correspondent` still apply with the controls off |
| T-30-SC | Tampering | npm/pip/cargo installs | accept | This plan installs nothing; every htmx token used is present in the vendored 2.0.8 bundle |
</threat_model>
