<objective>
Stop one row carrying two different facts, and get the gate out from under an unbounded resolver.

Purpose (R2-WR-02): plan 30-25 fixed *where* `skip_scanner` comes from and single-flighted the two
web checkers so they cannot contend with each other. It did not change what a failed gate acquire
renders as. `_scanner_result` still returns `_scanner_skipped()`, whose message is literally
"Not checked while a scan is running." (`checks.py:809`). So the only question left is whether
anything other than a scan can hold that gate, and something can:
`ScanWorker._read_generated_profiles` takes `with self._scanner_gate:` around `get_devices()` **and**
`get_capabilities()` (`worker.py:947`) as the worker thread's first act at startup, while
`_current_job_id` is still `None` -- it is not set until `worker.py:1394`, inside `_process_job`.

That window is the most likely contention window in the product, because it coincides exactly with
the cold-start poll: the lifespan starts the worker and then the refresher (`app.py:290-295`), a
browser on the appliance loads the page, the cold cache emits the poll, `note_watcher` stamps, the
next tick probes, `_check_scanner` tries the gate, and the startup capability read owns it -- for
seconds with a real scanner, or up to about 127 s for an unreachable net host. `_scanner_skipped()`
is stored, and the strip renders "Not checked while a scan is running." with `scan_active=False`,
beside "Last checked 14:02", on an appliance that has never scanned. The same round added a
sentence to `docs/reference/web-api.md:147` asserting this is impossible; the refresher's own
admitted residual (`refresher.py:253-258`) falsifies it a second way, for up to one TTL after any
scan ends. The existing regression test misses it because it stubs `run_checks` and asserts only
the flag (`tests/test_refresher.py:340-359`).

Purpose (R2-IN-03): plan 30-25 correctly narrowed the gate to `_check_scanner` alone -- but
`_check_scanner`'s *first* act is the saned pre-probe, whose name resolution is explicitly outside
every budget in this module (`checks.py:80-86`, and the paragraph 30-28 deliberately left intact).
So `ScanWorker._scan_job`'s `with self._scanner_gate:` can still park, with the job row already
written `SCANNING`, for as long as a broken resolver takes -- and `POST /api/checks/refresh` can
re-arm that every couple of seconds. The pre-probe touches no libsane state at all: it is DNS and a
TCP handshake. It has no business inside the lock whose one job is to keep two callers out of
libsane.

Output: a neutral contention row that names no scan, a scanner check whose gated region is exactly
the enumeration, documentation that matches, and a test that asserts the rendered row rather than
the flag.
</objective>
