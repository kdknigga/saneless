<objective>
Make the appliance's one manual control always deliver an answer, and record that the poll's
error-path residual is not a residual in this application.

Purpose (R2-WR-03): `POST /api/checks/refresh` does three things in sequence and they compose
badly. `claim_manual_refresh()` stamps the 2 s floor *before* `probe_now()` discovers it has
nothing to do, so a collapse spends the claim and the user's next click inside two seconds is
refused. `probe_now()` returns silently when `_probe_lock` is already held, and returns `None`
either way, so the route cannot tell a probe from a collapse. The response then renders
`_checks_context(state)` from the cache *as it stands now*, which is the pre-probe entry, because
the in-flight probe has not called `store()` yet. And because results already exist, `poll_attempt`
is `None`, so the body carries no htmx trigger at all -- nothing on the page will ever pick up the
result the in-flight probe lands a second later. The strip is refetched only by another click, the
terminal-state reload, or a page load. So the button can visibly do nothing, twice in a row, while
`docs/reference/web-api.md:149` tells the user "the answer the in-flight refresh is about to
produce is the same answer, seconds away." It is -- but nothing delivers it. The collision window
is one background probe's duration out of every TTL, and the Paperless read budget alone is 5 s.

Purpose (R2-IN-04): the review claims the attempt cap fails to bound the poll when `/api/checks`
returns a non-2xx, because "htmx does not swap on an error response" so the old body keeps its
`every 2s`. That is true of htmx's *default* `responseHandling` and false here.
`base.html:11-12` ships a customised `htmx-config` meta whose third rule is
`{"code":"[45]..","swap":true,"error":true}` -- this application swaps 4xx and 5xx responses.
Measured in Chromium against the vendored `htmx-2.0.8.min.js` with that exact meta, a polling body
whose endpoint returns 500 issues **one** request in a nine-second window and is then replaced by
the error body; the poll stops. The same rule covers the 422 the review posits for a hand-crafted
`attempt`. There is no defect to fix, so this plan pins the property instead of changing it.

Output: a refresh handler that distinguishes a probe from a collapse and gives the floor back, a
strip that keeps asking exactly as long as a probe is in flight, a browser measurement recording
IN-04's non-reproduction, and documentation that matches.
</objective>
