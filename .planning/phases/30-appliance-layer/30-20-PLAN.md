<objective>
Stop the web Profiles row lying on every config-file deployment, and make the fact it reports
impossible to compute two different ways.

Purpose: CR-01 is the one defect that breaks D-02 outright -- `saneless doctor` prints
`[ OK ] Profiles  2 scan profiles configured.` while the strip prints a permanent amber
`Generated in memory — no configuration file is in use…` for the same machine, and every clause of
that amber sentence is false. The cause is that `ScanWorker.__init__` seeds an in-memory member as
a "not attempted yet" marker and `_generate_startup_profiles` returns at `if not bare: return`
(`worker.py:889`) before any branch rewrites it. The fix is not just the branch: the derivation
lives in two places (`worker.py` and `cli.py:1155`) and only one of them was ever right, so this
plan makes it one function both call.
Output: `config.profile_storage_for_loaded`, two corrected early returns, `doctor` on the shared
derivation, and the agreement test that would have caught this.
</objective>
