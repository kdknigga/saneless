<objective>
Put a floor under the one handler that is allowed to probe, without taking away the reason it
exists.

Purpose: `POST /api/checks/refresh` deliberately bypasses the TTL and has no rate limit, no debounce
and no single-flight against a serial caller. `CrossOriginGuard` allows a request carrying neither
`Sec-Fetch-Site` nor `Origin` -- documented, and exactly what `curl` in a loop sends -- so each call
issues a Paperless HTTP request, up to N saned TCP dials and two filesystem writes. `GET /api/checks`
carries the documented guarantee that "watching the page cannot generate scanner or paperless-ngx
traffic"; this POST is the hole in it and the docs do not say so. On a LAN with no authentication
the marginal risk over `POST /api/scan` is small, but the scan-starvation effect is new: the
worker's `with self._scanner_gate:` is not a fair lock, so a tight refresh loop can park a submitted
job indefinitely while its row reads `SCANNING`. Plan 30-25 narrowed the hold window and collapsed
*concurrent* callers; a serial loop is what is left.
Output: a minimum interval enforced in `CheckCache`, a too-soon click that simply re-renders, and a
reference doc that admits the limit.
</objective>

| refresh handler → paperless-ngx, saned, filesystem | each honoured call is a request, up to N TCP dials and two file writes |
| refresh handler → `worker.scanner_gate` | contention here delays a job whose row already reads SCANNING |

| T-30-26-01 | Denial of service | probe amplification through the TTL bypass | mitigate | `claim_manual_refresh` enforces a minimum interval inside `CheckCache`, under the cache's own lock, so serial and concurrent callers alike are capped at one probe per interval. Pinned by a twenty-request loop asserting one probe and one Paperless request. |
| T-30-26-02 | Denial of service | scan starvation behind an unfair scanner gate | mitigate | With the probe rate capped and plan 30-25's narrowed hold window, the gate is free between probes, so a submitted job can no longer be parked indefinitely by a refresh loop. |
