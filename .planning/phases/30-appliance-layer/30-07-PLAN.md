<objective>
Build the two service objects that make the status strip fast: a TTL cache that keeps the previous
answer, and a lazy daemon thread that refills it only while someone is looking.

Purpose: D-04's whole point is that a page render never probes. An unplugged scanner host means a
TCP connect that hangs until the OS gives up, so the mechanism has to be "the page reads a cache
that a background thread fills", not "the page probes quickly".
Output: `web/checks_cache.py`, `web/refresher.py`, and their sleep-free tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| background thread -> Paperless client and SANE backend | A non-request thread makes network and device calls |
| request thread -> refresher watch timestamp | Any page load can extend the window in which the appliance probes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-26 | Denial of service | unbounded probe rate driven by page loads | mitigate | The TTL (D-03) bounds probes to one per 30 s regardless of how many watchers stamp the timestamp, and the watch window (D-05) stops probing 90 s after the last page load. `note_watcher` only writes a float; it cannot trigger a probe directly |
| T-30-27 | Denial of service | the refresher probing the scanner mid-scan | mitigate | `_tick` acquires the worker's `scanner_gate` non-blocking and sets `skip_scanner` when it cannot, so no SANE call is made during a scan (D-08, Pitfall 2) |
| T-30-28 | Denial of service | a stuck probe blocking process exit | mitigate | Daemon thread, stop `Event`, `Event.wait` idle sleep and a join bounded by the shared `STOP_JOIN_SECONDS`; `stop()` reports whether it actually stopped so the lifespan can decide what to close (plan 30-09, Amendment A-7) |
| T-30-29 | Information disclosure | logging a failed probe | mitigate | The failure log records that the refresh failed, not the exception's rendered message into any user-facing surface; the cache retains the previous developer-constant rows |
| T-30-30 | Tampering | concurrent stores corrupting the cache entry | mitigate | One lock guards the whole store-and-stamp; a barrier test asserts consistency |
| T-30-SC | Tampering | npm/pip/cargo installs | accept | This plan installs nothing |
</threat_model>
