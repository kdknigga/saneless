<objective>
Stop holding the lock that keeps two callers out of libsane while nothing is inside libsane, and
stop reporting checker-versus-checker contention to a household member as "a scan is running".

Purpose: WR-03 and WR-04 are one design fault with two faces. Both probe sites acquire
`worker.scanner_gate` and hold it across the *whole* of `run_checks`, although only
`_check_scanner` touches SANE -- `_check_paperless` has a `httpx.Timeout(5.0, connect=2.0)` budget
of up to ~7 s and `_check_fallback` / `_check_data_dir` each create and delete a real file. So the
gate is routinely held for ten seconds or more with nothing inside SANE, while
`ScanWorker._scan_job` blocks on `with self._scanner_gate:` with the job row already written
`SCANNING`: the status area reads "Scanning…" while the worker is parked behind a Paperless health
probe. And because `skip_scanner = not acquired` treats *any* failed acquire as a running scan, a
Check again click landing during a refresher tick renders "Not checked while a scan is running"
beside "Last checked 14:02" on an idle appliance -- a self-contradicting strip that
`docs/reference/web-api.md` says cannot happen.
Output: a gate held only around the scanner check, one single-flighted probe path both callers
share, and a skip derived from the fact it claims.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN browser → `POST /api/checks/refresh` | an unauthenticated request causes outbound probes |
| request thread ↔ refresher thread ↔ worker thread | three threads contend for one scanner gate |
| server → LAN browser | the strip's rows are read by a non-technical household member |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |

| T-30-25-01 | Denial of service | `worker.scanner_gate` held across `run_checks` | mitigate | The gate is acquired non-blockingly around `_check_scanner` only, so a Paperless timeout or a filesystem write can no longer park `ScanWorker._scan_job` with the job row already `SCANNING`. Pinned by assertions taken from inside each non-scanner check. |
