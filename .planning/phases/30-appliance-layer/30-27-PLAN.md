<objective>
Give the cold-start poll an end that does not depend on the refresher thread staying alive.

Purpose: `checks.html` emits `hx-trigger="load, every 2s"` whenever `checks is none`, and the only
thing that ends it is results landing in the cache. If the refresher thread dies, or if the watch
window and gate contention keep every tick from storing, an open tab polls `/api/checks`
indefinitely. Each request is cheap -- one cache read -- but the poll is unbounded by design, and
the appliance is meant to be left open on a tablet in a hallway.
Output: a bounded attempt counter the server owns, a give-up state that still shows the rows and
the button, and a browser measurement proving the legitimate cold start is untouched.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| open browser tab → `GET /api/checks` | an abandoned tab generates requests indefinitely today |
| query string → route handler | `attempt` is request input reaching the response context |
| server → LAN browser | the give-up line is rendered on a LAN-visible page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-30-27-01 | Denial of service | the unbounded cold-start poll | mitigate | The server stops emitting the trigger after a bounded number of attempts, so a tab left open against a dead refresher stops. Each request was already a cache read and never a probe, so the exposure being closed is request volume, not upstream traffic. |
| T-30-27-02 | Tampering | the `attempt` query parameter | mitigate | Bounded by `Query(ge=0, le=POLL_ATTEMPT_CAP)` at the route boundary, following the `max_length` idiom already used for the tag filter, so a crafted value is rejected by validation and never reaches the context or the template. |
| T-30-27-03 | Information disclosure | the give-up line | mitigate | A developer constant in `checks.py` beside `CHECKING_MESSAGE`, carrying no path, URL, host or exception text, and the `attempt` value is never echoed into the visible body -- only into the next request's URL. |
| T-30-27-04 | Denial of service | a self-re-arming `outerHTML` swap target | mitigate | The htmx request attributes stay inside a conditional and the condition is now supplied by the server; pinned by a rendered-HTML assertion that the capped body carries no `hx-` attribute at all. |
| T-30-27-SC | Tampering | npm/pip/cargo installs | n/a | No package is installed; htmx stays on the vendored 2.0.8 and no client script file is introduced (Phase 26 deleted `app.js` and this plan does not bring one back). |
</threat_model>
