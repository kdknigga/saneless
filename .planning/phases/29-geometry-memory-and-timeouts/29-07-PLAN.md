<objective>
Replace the per-call `ThreadPoolExecutor` with a daemon-thread acquisition helper that cancels,
waits, and closes only if the read returned — and wedges the backend honestly when it did not.
Bring the flatbed path through the same helper. Prove all of it with an Event-gated fake and a
subprocess.

Purpose: HARD-03 and HARD-04. A `ThreadPoolExecutor` worker stuck in a blocking C call makes the
process hang at exit forever (measured on CPython 3.14.2); a `daemon=True` thread stuck in the
identical call lets it exit in 0.24 s.
Output: `_acquire_with_timeout`, `_cancel_and_settle`, `_CANCEL_GRACE_SECONDS = 10.0`, a
module-level wedge record, a flatbed path under the same timeout, and the tests that prove them.
</objective>
