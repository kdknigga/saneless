## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-supplied job title → `failed/` names | Both the `(partial)` PDF name and the page-directory name derive from the title |
| per-job `TemporaryDirectory` → `<data_dir>/failed/` | Artefacts cross a filesystem boundary during preservation |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-34 | Tampering | path traversal through a job title reaching `failed/` | mitigate | Both names go through `build_pdf_filename`, which composes a timestamp, a truncated job segment and `sanitise_title_for_filename`'s existing allow-list with a 60-character cap. The directory name is the same string's stem, so it inherits the sanitiser unchanged (ASVS V5) |
| T-29-35 | Tampering | `shutil.move` to a bare directory | mitigate | Every move names an explicit destination path. `shutil.Error` is not an `OSError` and would escape the guard's handler, which is the documented reason `_preserving` already does it this way (ASVS V12) |
| T-29-36 | Denial of service | unbounded growth of `failed/` | mitigate | `_warn_if_failed_dir_growing` now counts directories as well as PDFs and reports the combined size, so the operator is warned. saneless deliberately never prunes `failed/` (Phase 23 OUTC-04) |
| T-29-37 | Repudiation | a preserved cancel | mitigate | `ScanCancelledError` is re-raised before the preservation branch. A broad `except Exception` would otherwise keep a scan the operator chose to abandon, in a directory that is never pruned |
| T-29-38 | Information disclosure | preservation messages | accept | Messages name page counts and filesystem paths under `data_dir` only; no token or credential is in scope (ASVS V7) |
| T-29-39 | Tampering | a bookkeeping failure masking a delivery failure | mitigate | The growth walk stays inside the existing `try` with its silent `except OSError: return`, and its "must never raise" docstring paragraph is preserved |
</threat_model>
