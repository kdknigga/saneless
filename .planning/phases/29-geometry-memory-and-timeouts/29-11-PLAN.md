<interfaces>
The delivered behaviour these documents must now describe (take the exact message wordings from
29-09-SUMMARY.md, which records them):

- Pages are spooled to disk as PNG (Pillow's default compression level 6) as they arrive, each with
  an ordered `PageRecord`; order comes from the record list, never from the filesystem.
- Peak memory during scanning is roughly one decoded page (measured high-water mark of live page
  images: 2, independent of page count). Peak memory during assembly is flat in page count
  (measured 131 MB at both 12 and 48 pages) because assembly converts one page at a time and merges
  with qpdf.
- Disk is checked per page against that page's decoded size, keeping `min_free_space_mb` in reserve
  for assembly.
- One per-page timeout, `_DEFAULT_PAGE_TIMEOUT_SECONDS` = 120 s, bounds both the ADF and the
  flatbed path. On timeout: cancel, wait `_CANCEL_GRACE_SECONDS` = 10 s, close only if the read
  returned.
- A read that never returns wedges the backend: the next scan is refused with a message telling the
  operator to restart saneless, and it recovers by itself if the read eventually returns. A stuck
  read never blocks process exit, `docker stop` or `pytest`.
- A mid-batch failure after N pages keeps those N pages as a `(partial)` PDF under `failed/`; a
  pass-B or flip failure keeps the fronts as a `(fronts)` PDF; a `PdfError` during assembly keeps
  the page files in a `failed/<job-keyed-name>/` directory; a cancel keeps nothing.
- SANE is initialised once per process and shut down after the worker confirms it stopped.
