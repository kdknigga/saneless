<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator-supplied job title → filesystem | Titles reach `failed/` names through `build_pdf_filename`; the spool must not widen that surface |
| scanner → process memory | A device-supplied image of arbitrary size is decoded and written to disk |
| process → local filesystem (`tmp_dir`) | New per-job writes land inside the per-job `TemporaryDirectory` |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-01 | Tampering | `SpooledPageSink` file naming | mitigate | Spool names are `f"{pass_label}-{sequence:04d}.png"` — derived from an integer counter and a fixed pass label, never from the operator's title, so no traversal input reaches the name (ASVS V5) |
| T-29-02 | Denial of service | `SpooledPageSink.add` disk writes | mitigate | Per-page free-space check against the decoded page size plus the `min_free_space_mb` assembly reserve (D-07), on top of the existing `_MAX_ADF_PAGES` cap of 500 |
| T-29-03 | Information disclosure | `ScanError` messages from the spool | mitigate | Messages name the page number, the spool path and free/required MB only; no token, credential or device password is in scope (ASVS V7) |
| T-29-04 | Denial of service | Decompression-bomb PNG on read-back | accept | Not reachable: the spool only ever reads back files it wrote itself; `MAX_IMAGE_PIXELS` consolidation is N-10 / Phase 32 |
| T-29-SC | Tampering | `uv add pikepdf` | mitigate | RESEARCH.md § Package Legitimacy Audit: PyPI, 8+ years, millions of downloads/month, github.com/pikepdf/pikepdf, slopcheck `[OK]`; already installed as an unconditional transitive dependency of img2pdf, so no new code enters the environment |
</threat_model>
