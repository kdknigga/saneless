<objective>
Make HARD-01's memory sentence true end to end on the assembly side: convert one page at a time
with `outputstream=`, then merge the single-page PDFs with qpdf through `pikepdf.Job`.

Purpose: research measured that `img2pdf.convert` builds the whole document in memory before
writing a byte, so `outputstream=` alone leaves assembly linear in page count — 787 MB at 48 pages,
extrapolating to gigabytes at 500. Per page plus a qpdf merge measured **flat at 131 MB for both 12
and 48 pages**, with byte-identical image streams, identical MediaBoxes and the same wall clock.
Output: a bounded `assemble_pdf`, and tests that prove both the equivalence and the flatness.

This is CONTEXT.md's one research-driven amendment to a locked decision. Both of D-03's locked
clauses — the spooled PNG is exactly what img2pdf embeds, and `outputstream=` is passed — remain
literally true in this shape. Only the assumption that `outputstream=` bounds memory was wrong.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| spooled PNG → img2pdf | Files the process wrote itself are re-read during assembly |
| single-page PDFs → qpdf via pikepdf.Job | An argv is constructed and handed to a native library |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-29 | Tampering | the `pikepdf.Job` argv | mitigate | Every path in the argv is a file this function just created inside its own `TemporaryDirectory` under `output_dir`; no operator-controlled string enters the argv, and `pikepdf.Job` is an in-process qpdf API, not a shell invocation (ASVS V5) |
| T-29-30 | Denial of service | assembly memory on a 500-page job | mitigate | This plan is the mitigation: per-page convert plus a lazy qpdf page copy, measured flat at 131 MB at any page count |
| T-29-31 | Denial of service | `Job.run()` holding the GIL | accept | Measured at roughly 12 ms per page, so about 6 s for a 500-page job, on the worker thread that is already blocked for the whole scan. Visible as a briefly frozen status poll, not as data loss (RESEARCH.md assumption A4) |
| T-29-32 | Tampering | a PDF parsed during assembly | accept | The only PDFs qpdf reads are the single-page files this function just wrote; no untrusted document enters the merge |
| T-29-33 | Denial of service | the child process in the memory test | mitigate | Non-shell `subprocess.run` with an explicit timeout, matching the existing `test_atomic_write.py` pattern |
</threat_model>
