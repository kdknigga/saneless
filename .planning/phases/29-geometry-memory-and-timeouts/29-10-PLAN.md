- A module-level **mutable container** holding the init state: whether `sane.init()` has run in this
  process, the host that was used, the SANE version it returned, and an `threading.Lock`. It is
  mutated, never rebound — ruff `PL` is selected, so a `global` rebind triggers `PLW0603`, and
  CLAUDE.md forbids adding a new `# noqa`. The existing `_ensure_sane`'s `global sane` line already
  carries one; do not copy that pattern. Where practical, fold this state into (or alongside) the
  wedge record plan 07 introduced, so the module has one place for process-global state rather than
  two.
- `_ensure_initialised(host)` (name is the planner's; keep it module-private) — takes the lock, and
  on the first call in the process sets `SANE_NET_HOSTS` and calls `sane.init()`. On a later call
  with a different non-empty `host`, logs a WARNING naming **both** hosts and does nothing else.
- `shutdown() -> None` — module-level, idempotent. Calls `sane.exit()` and resets the init state so
  a later init is allowed. Skips and logs when the wedge record says a reader is still inside SANE.
  Never raises.
- `SaneBackend.close(self) -> None` — overrides the concrete base method, delegating to `shutdown()`.
  It is logged, never raised, following `_open_device`'s `finally` rule: an exception from a close
  would replace the error the operator needs to see.

`src/saneless/cli.py` — the four `SaneBackend(` construction sites are currently at :543 (`scan`),
:640 (`devices`), :761 (`serve`) and :861 (`auto-profiles`). `serve` is already wrapped in the
`ScanError` to `ConfigError` translation that must not be disturbed, and its backend is closed by
the lifespan, not by the command.

`src/saneless/web/app.py` — the lifespan shutdown branch currently ends

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| HTTP request → process-global SANE state | Any route that reached `sane.init()` or `sane.exit()` would let a request mutate process-global state |
| operator config (`scanner.host`) → `SANE_NET_HOSTS` | A config value becomes a process environment variable |
| process shutdown → open SANE handles | `sane_exit` closes every open handle |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-29-40 | Elevation of privilege | a request path reaching `sane.init()` / `sane.exit()` | mitigate | D-19's `TestClient` proof drives every route and asserts `init_call_count` stays 1 and `exit_call_count` stays 0 until shutdown — behaviour, not a grep that a new route could evade (ASVS V4) |
| T-29-41 | Tampering (memory safety) | `sane.exit()` with a read outstanding | mitigate | `shutdown()` checks the wedge record and skips, and the lifespan's worker-did-not-stop branch still returns early without closing. `PySane_exit` runs holding the GIL and closes every open handle |
| T-29-42 | Spoofing | a second host silently ignored | mitigate | D-17 upgrades the existing INFO to a WARNING naming both hosts, so an operator cannot believe a host is in effect when SANE only read the first (N-04) |
| T-29-43 | Denial of service | a raising `close()` replacing the real error | mitigate | `close()` and `shutdown()` log and swallow, following `_open_device`'s existing logged-never-raised rule; Finding 10 notes a raise from a click close callback would replace the real error |
| T-29-44 | Information disclosure | the host WARNING | accept | It names hostnames from the operator's own config, which already appear in logs today via the existing INFO line. No token is in scope (ASVS V7) |
| T-29-45 | Tampering | `atexit`-based teardown | mitigate | Explicitly rejected: `atexit` would run while a daemon reader thread may still be inside `sane_read`. Teardown is at the entry point, per review principle 7 |
</threat_model>
