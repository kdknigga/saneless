<objective>
Vendor htmx 2.0.8 and Pico 2.1.1 into the package with SHA-384 integrity, and pin the bytes so
they cannot silently drift (ROBU-09, N-21, M-33 enabler).

Purpose: the UI must work on an offline LAN, and the browser tests can only move into CI once no
CDN is involved (plan 26-12). Research Pitfall 1: the repo's byte-rewriting prek hooks would append
a newline to both minified files at commit time and the browser would then refuse them over the SRI
mismatch, so the hook exclusion lands and is committed first.

Output: four vendored files, base.html pointing at them, a hook exclusion, `.gitattributes`, and
`tests/test_vendor_assets.py`. The `htmx-config` meta (26-05) and the `app.js` tag removal (26-11)
are NOT part of this plan.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| npm registry -> repository | third-party bytes enter the package |
| package static files -> browser | the browser executes/applies the vendored bytes |
| commit hooks -> committed bytes | tooling can rewrite files |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-07 | Tampering | CDN compromise or offline CDN (N-21) | mitigate | Assets served from the package; no external URL in templates (test) |
| T-26-08 | Tampering | substituted/corrupted tarball during vendoring | mitigate | Tarball SHA-512 checked against registry `dist.integrity`; file SHA-384 checked against the research pin before commit; stop on mismatch |
| T-26-09 | Tampering | hooks or EOL conversion altering vendored bytes | mitigate | top-level prek `exclude`, `.gitattributes -text`, post-commit `git show` hash check, bytes-vs-integrity test |
| T-26-10 | Denial of service | SRI mismatch leaves the UI unstyled/unscripted | mitigate | `tests/test_vendor_assets.py` in the fast CI job fails before a browser ever sees it |
| T-26-SC | Tampering | npm packages (htmx.org@2.0.8, @picocss/pico@2.1.1) | mitigate | Research Package Legitimacy Audit: both [OK] via slopcheck, long-lived, source repos verified; nothing installed, two files copied; no [ASSUMED]/[SUS] entries so no human checkpoint is required |
</threat_model>
