<objective>
Reject cross-site state-changing requests (ROBU-10, N-22) with a Go 1.25 `CrossOriginProtection`-style
check that also works on saneless's documented plain-HTTP LAN deployment (D-20..D-23).

Purpose: browsers send `Sec-Fetch-Site` only to secure contexts, so on `http://<lan-ip>:8080` it is
absent and a Sec-Fetch-Site-only rule would protect nothing. The Origin-vs-Host fallback covers that
branch, and the tests exercise it explicitly (TestClient sends neither header by default, so the
plain-HTTP branch is directly testable). The optional real-browser LAN-IP proof of assumption A6 is
plan 26-13 Task 3.

Output: `web/cross_origin.py`, middleware wiring, `tests/test_cross_origin.py`. Docs for proxy
Host preservation are plan 26-14.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| third-party web page in the operator's browser -> saneless POST endpoints | cross-site form or fetch |
| reverse proxy -> saneless | proxy decides Host / X-Forwarded-Host |
| request headers -> server log | attacker-chosen header values are logged |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-26 | Tampering (CSRF) | cross-site POST starting a scan or answering a flip (N-22) | mitigate | `CrossOriginGuard` on every unsafe method; branch 1 + branch 2 tests; generative route test |
| T-26-27 | Spoofing | forged X-Forwarded-Host from a malicious page | mitigate | A custom header forces a CORS preflight that saneless never approves, so browsers never send it (D-21); non-browser clients are not CSRF vectors (branch 3) |
| T-26-28 | Tampering | `Origin: null` (sandboxed iframe, data: URL) | mitigate | Empty origin host is rejected; tested |
| T-26-29 | Repudiation / log injection | crafted Origin/Host values | mitigate | `%r` formatting; test with an embedded newline |
| T-26-30 | Denial of service | legitimate users behind a misconfigured plain-HTTP proxy get 403 | accept | Documented Host/X-Forwarded-Host guidance (26-14); 403 message names the proxy; log line names all headers |
| T-26-31 | Elevation of privilege | future POST route without protection | mitigate | App-wide middleware (D-23) with a test that adds a new route |
| T-26-SC | Tampering | package installs | accept | None |
</threat_model>
