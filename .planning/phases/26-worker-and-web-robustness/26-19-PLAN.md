<objective>
Close IN-08 from the fresh 26-REVIEW.md. 26-VERIFICATION.md recommended it for this remediation pass.

Purpose: POST /api/scan creates the job row before `worker.submit()` (D-05). When `submit()` refuses
(queue full, down, degraded), `_reject_created_job` (src/saneless/web/routes.py ~317-359) finishes that
row as ERROR/REJECTED. If that write fails, it calls `worker.owe_rejection(job_id, error)`, and the
worker writes the row on a later idle tick. Until that tick the row is PENDING with no REJECTED marker.
So while no job is current, `_current_or_recent_job` (routes.py ~90-121) gets it from
`JobStore.latest_run_job()` and renders "Starting scan..." with `#scan-btn` disabled, for a scan that
was refused and never ran. That violates D-06 ("the rejected-submit row must not hijack the status
area"). It can last more than one tick:
- For QUEUE_FULL, idle ticks only come once the queue drains.
- For a store that stays broken, it lasts until the row lands.
- For a worker thread that is truly down, it lasts until restart.

Fix, per IN-08's suggested fix: the status lookup also skips ids the worker still owes a REJECTED write
for. This is exactly D-06's existing rule (skip rows rejected at submit), applied to a rejection that is
not written yet. It does not change D-17's contract, so no user escalation is needed. Only owed
REJECTED entries are skipped. A guard-owed failure belongs to a job that ran, so D-17 still reports it.

Mechanism (Claude's discretion): a keyword `exclude_ids` on `JobStore.latest_run_job`. It is implemented
by binding a row LIMIT of `len(exclude_ids) + 1` and filtering in Python. That is correct because at
most `len(exclude_ids)` newer rows can be skipped. It keeps the SQL a constant with only bound
parameters, and no id is ever interpolated. `ScanWorker.owed_rejection_ids()` exposes the owed set
without leaking the private dict or its lock.

Accepted residual window, documented in the `_current_or_recent_job` docstring: one request's own
store round trip, between `create_job` and either the successful REJECTED write or the `owe_rejection`
call after it failed. A poll can only land there for the duration of that one write attempt, and WR-01
already noted it.

Output: RED tests at the store, worker and web layers, then the GREEN change in three src files.

- IN-06 (no final flush at shutdown).
