<objective>
Move auto-profile generation out of the first job and into the worker thread's startup, writing to
the config file that was actually loaded (ROBU-07, M-04, D-14..D-19).

Purpose: today generation runs inside `_process_job`, writes to `resolve_config_path()` (which
ignores `--config` and can drop `./saneless.toml` into the daemon's CWD), and mutates
`settings.profiles` from the worker thread with no lock. Decision on Claude's discretion item
"replace vs merge": REPLACE the bare `default` entry (generation only runs on the exact full-model
bare default, and DPLX-07 always emits a `default`), re-checked under the D-19 lock.

Output: `_generate_startup_profiles`, deletion of `resolve_config_path` and its test class,
startup-generation tests, and test fixture adjustments for Pitfall 2.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| scanner (SANE) -> generated profiles | device-reported capabilities shape config |
| worker thread -> filesystem | profile persistence writes a file |
| worker thread <-> request threads | profile set replaced while requests read it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-32 | Tampering | write to a re-derived path (CWD `./saneless.toml`, `$HOME`, `/`) | mitigate | Write target is only `settings.config_path`; None -> memory only; test asserts no file appears in the CWD |
| T-26-33 | Tampering (race) | profiles mutated while a `def` route iterates them | mitigate | Rebind under `_profiles_lock` after re-checking `is_bare_default` (D-19) |
| T-26-34 | Repudiation | misleading "scanner unreachable" log | mitigate | WARNING names `type(exc).__name__` with exc_info (D-15); test asserts the old text is gone |
| T-26-35 | Denial of service | generation blocking startup or a job forever | accept | Generation runs on the worker thread after the server is serving; a hung SANE call is the same abandon case D-07 accepts; HARD-03 (Phase 29) owns SANE cancellation |
| T-26-SC | Tampering | package installs | accept | None |
</threat_model>
