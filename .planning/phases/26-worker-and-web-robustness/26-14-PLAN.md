Facts to document (read the code to confirm each before writing it):
- `/health`: 200 `{"status": "ok"}`; 503 `{"status": "error", "detail": "job store failing"}` (degraded after 3 consecutive job-store/prune failures; clears itself when a store probe succeeds, checked every 5 s while idle); 503 `{"status": "error", "detail": "worker thread is down"}`.
- `POST /api/scan`: 200 status partial (plus out-of-band Scan button and message clear); 422 unknown profile / title over 256 characters (no job created); 429 queue full (10 queued), `Retry-After: 30`, rejected attempt recorded in history as failed; 503 worker down or degraded (recorded when the store accepts it); 403 cross-site.
- `POST /api/cache/invalidate`: `resource` must be `tags` or `correspondents`, else 422.
- Every error: with `HX-Request: true`, an HTML fragment plus `HX-Retarget: #status-message` / `HX-Reswap: innerHTML`; otherwise `{"status": "error", "detail": "<message>"}`; same status code both ways.
- Cross-site guard on every non-GET/HEAD/OPTIONS request: `Sec-Fetch-Site` same-origin/none allowed, same-site/cross-site 403; without it, `Origin` must match `Host` or `X-Forwarded-Host`; neither header (curl, scripts) allowed. Behind an HTTPS proxy the browser sends Sec-Fetch-Site so Host does not matter; behind a plain-HTTP proxy the proxy must preserve Host (`proxy_set_header Host $host;`) or set `X-Forwarded-Host`. A proxy that adds `Referrer-Policy: no-referrer` can make browsers send `Origin: null`, which is rejected (research assumption A4 -- verify before writing; if unverifiable, omit that sentence).
- Shutdown: stop flag, up to 5 s wait; an in-flight scan is abandoned and marked "The server restarted before this scan finished" at the next start; queued jobs are also failed at the next start.
- Startup: jobs left active are failed with that reason before the worker starts; if the store cannot be written at startup, the app starts degraded.
- Startup profile generation (serve): once, only when the profile set is the untouched default; writes to the config file that was loaded (`--config` or the first found search location); no file loaded -> used for this run only, nothing written; unwritable file -> used for this run only with a warning. `saneless auto-profiles` writes to the loaded file, else `./saneless.toml`.
- Web UI assets: htmx 2.0.8 and Pico 2.1.1 are served from the package; no internet needed; no app JavaScript.
Current doc lines: web-api.md 33-42 (health), ~70-90 (scan), 170-173 (notes); architecture.md 48-56 (worker model), 84-87 (web layer, app.js sentence); configuration.md 55 (`web_host`); environment-variables.md 56; cli-commands.md 116 (`--host`) and 125-160 (auto-profiles); docker.md 16-23 (healthcheck); deploy-docker-compose.md (no proxy section yet); configure-scan-profiles.md 137-158.
