<objective>
Build the single error-rendering path (D-01..D-04) and its client half (the `htmx-config` override
and the `#status-message` slot), so that every error the server produces is something the user can
actually see, in one place, without hijacking the status area.

Purpose: htmx 2 drops 4xx/5xx bodies by default, so a 429 would be invisible -- the exact C-10
symptom this phase fixes. Routes (26-10) and the cross-origin middleware (26-07) will only raise or
call into this; neither builds error HTML.

Output: `web/errors.py`, `partials/error.html`, handler wiring in `create_app`, the meta, the slot,
one CSS rule, and `tests/test_web_errors.py` exercised through test-only routes (the real routes
start raising in 26-10).
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| LAN client -> error responses | untrusted request data reaches validation and exception paths |
| server exceptions -> client | internal failure detail could leak |
| error response -> DOM | swapped HTML lands in the page |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-26-16 | Information disclosure | catch-all 500, 422 detail | mitigate | Fixed vocabulary messages only; tests assert exception class/text and input markers absent on both branches; traceback only in server log |
| T-26-17 | Tampering (XSS) | error partial | mitigate | Message is a developer constant through Jinja autoescape; no request value is ever in the context |
| T-26-18 | Tampering (DOM) | error swapped into a `<select>` or the history table | mitigate | `HX-Retarget: #status-message` + `HX-Reswap: innerHTML` on every htmx error (D-02); tested for every rejection |
| T-26-19 | Repudiation / log injection | validation logging | mitigate | Logs only `(loc, type)` pairs, never `input`/`msg`; test checks caplog for the marker |
| T-26-20 | Denial of service (UX) | invisible 429 (htmx drops 4xx) | mitigate | htmx-config restating all three entries; structural test here, browser proof in 26-13 |
| T-26-SC | Tampering | package installs | accept | None |
