<objective>
Close the first half of WR-01. A refused scan submit recorded before any job row exists must be one
atomic write, so a store failure can never leave a PENDING row with no REJECTED marker.

Purpose: `_record_rejected_submit` (src/saneless/web/routes.py ~277-320) runs `create_job` (commits
PENDING) and then `finish_job(ERROR, REJECTED)` as two transactions. If the second raises, the
exception is swallowed (`return False`), and the row stays PENDING with `error_category` NULL. Nothing
reconciles it: the worker never saw the id, and `fail_active_jobs` runs only at startup or while
restart recovery is pending. `latest_run_job` does not skip it, so the status area shows "Starting
scan..." forever and `#scan-btn` stays disabled. This is the same symptom as CR-01, which 26-15 fixes
for worker-owned rows.

This plan adds `JobStore.create_rejected_job`, one INSERT of a terminal REJECTED row, and uses it for
the refused-before-row path (the `job_id=None` branch, reached when `_unhealthy_rejection` fires). It
also splits the route helper into two named helpers, so 26-17 can add the post-submit fallback without
threading an unused parameter through the pre-row path.

Output: a new store method, store tests, the route split and wiring, and a route test that fails today
for the real reason.

Out of scope: the post-submit branch's owed-write fallback (26-17, which needs 26-15's flush), and
WR-02..WR-09 and IN-01..IN-05.
</objective>
