<objective>
Close the second half of WR-01. A rejected-submit row that already exists (created before `submit()`
refused it) must not be stranded PENDING when its REJECTED write fails.

Purpose: in `start_scan`, the row has to exist before `put_nowait`, or the worker could dequeue an id
with no row (D-05). So a refusal from `submit()` (QUEUE_FULL, DOWN, DEGRADED) needs a second write.
After 26-16 that write lives in `_reject_created_job` and is only logged on failure. The row then
stays PENDING with no marker and no reconciliation: the status area shows it and `#scan-btn` is
disabled. Per 26-REVIEW.md WR-01's fix, hand the failed write to the worker
(`worker.owe_rejection(job.id, error)`). The worker's owed-writes flush from 26-15 retries it on every
idle tick. That flush is currently worker-thread-only, so it gains a lock.

Output: `ScanWorker.owe_rejection`, a locked owed-writes dict, the route fallback, worker and route
tests, and the architecture doc sentence extended.

Out of scope: WR-02 (success-write classification), WR-06, and the other review warnings and info
items.
</objective>
