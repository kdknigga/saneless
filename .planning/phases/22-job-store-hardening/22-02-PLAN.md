<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| module-level SQL construction → SQLite | Identifiers cannot be parameterised, so the column list is interpolated into `SELECT` and `INSERT` statements. |
| stored row → `Job` | Values read out of a database file are turned into typed Python objects and enum members without static type checking. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-22-06 | Tampering (SQL injection) | `_SELECT_ALL`, `_SELECT_BY_ID`, `_SELECT_RECENT`, `_INSERT` in `src/saneless/job.py` | mitigate | The only interpolated values are `_COLUMN_LIST` and `_PLACEHOLDERS`, both derived at import from the module-level `_COLUMNS: tuple[str, ...]` literal. No caller-supplied value reaches the statement text; every runtime value is a bound `?` parameter. Statements are built once at import, so nothing is reconstructed from data at call time. Each constant carries a docstring stating this. Note the `S608` resolution is a naming form, not a suppression — ruff reports zero findings with zero `# noqa`. |
| T-22-07 | Information Disclosure | the `owner_token` column and `Job.owner_token` | accept | `owner_token` lands as an unwritten, unread nullable column this phase. Its semantics are fixed elsewhere: REQUIREMENTS.md § Out of Scope states it is a footgun guard for the Phase 30 flip prompt, NOT an auth mechanism, and APPL-09 pins it to an HttpOnly `SameSite=Lax` cookie. Nothing in this phase may treat it as a credential, log it, or render it. Accepting is correct because no code path reads it yet; Phase 30 owns the disclosure surface when it does. |
| T-22-12 | Tampering | `_row_to_job` enum reconstruction | mitigate | A stored `state`, `error_category` or `outcome` value the current enum does not know raises on read rather than being silently coerced — identical to today's `JobState(row[3])` behaviour and consistent with Phase 21's D-10. Because `sqlite3.Row.__getitem__` is typed `Any`, neither type checker can catch a wrong-typed value, so the `outcome_roundtrip` test asserts Python type as well as value; that test is the whole control. |
| T-22-SC | Tampering | package installs | accept | No packages installed in this phase (RESEARCH § Package Legitimacy Audit). |
</threat_model>
