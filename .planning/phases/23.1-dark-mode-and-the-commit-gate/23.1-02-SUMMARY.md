# Phase 23.1 Plan 02: The Commit Gate Summary

Split the type checkers across three git stages so a TDD RED commit can land while a type
error still cannot, and rewrote the pathless pyrefly command out of all four live files.

## What Shipped

**Task 1 — config B and CI** (`d236c18`)

`.pre-commit-config.yaml` gained two top-level keys, each with a one-line reason comment:
`default_install_hook_types: [pre-commit, pre-merge-commit, pre-push]` and
`default_stages: [pre-commit]`. Four upstream hooks whose own manifest declares
`[pre-commit, pre-push, manual]` (`check-added-large-files`,
`check-executables-have-shebangs`, `end-of-file-fixer`, `trailing-whitespace`) got an
explicit `stages: [pre-commit]`, because a top-level `default_stages` does not override a
manifest stage list.

The local repo now holds four type-check hooks instead of two. `ty-checker` and
`pyrefly-checker` keep their ids, take the `(src)` name suffix and are limited to `src`.
The new `ty-checker-full` and `pyrefly-checker-full` carry
`stages: [pre-merge-commit, pre-push]`. The existing five-line `use-ignore-files` comment
stayed attached to the pyrefly hook with its wording unchanged.

`.github/workflows/ci.yml`: the `lint` job's pyrefly step now names `src tests`. The step
above it and the job name are untouched, because ruleset 22777879 matches the required
check by name.

**Task 2 — documentation** (`71475d4`)

`CONTRIBUTING.md` got a new `## Where the type checkers run` section covering, in order:
the commit-time `src/`-only scope and why a RED commit lands; the full check at
`--no-ff` merges and at push; that `pre-push` inspects the checked-out working tree rather
than the refs being pushed; the conflicted-merge gap (finishing with `git commit` fires the
commit-stage hooks only); the four-step recovery from a hook-rejected merge via
`git merge --abort`; and the `use-ignore-files` reason for naming pyrefly's paths. The
"Setting up" block gained the hook-install step in its `--git-dir` form with the
`core.hooksPath` explanation, "The five checks" now spells pyrefly with paths in both the
table and the reproduce block (still five), "Local pre-flight" no longer claims the default
stage covers both type checkers in full, and the `--no-verify` section gained the merge and
push variants while keeping its original paragraph true.

`CLAUDE.md`: the Commands block names pyrefly's paths and adds
`uv run prek run --stage pre-push`, and Gotchas gained two bullets (the gitignored-worktree
filtering reason, and the stage split with an explicit ban on `--no-verify`, `SKIP=` and
stub-writing to force a RED commit through).

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Acceptance-criterion grep count is off by one**

- **Found during:** Task 1
- **Issue:** The criterion `grep -c 'stages: \[pre-commit\]$' .pre-commit-config.yaml == 4`
  cannot hold for a correct file. The pattern is unanchored, so it also matches the
  top-level `default_stages: [pre-commit]` line, which the criterion's own parenthetical
  says is "counted separately above". The correct file returns 5.
- **Fix:** No file change. Re-ran the count anchored to the 8-space per-hook indent,
  `^        stages: \[pre-commit\]$`, which returns exactly 4 — the intended four
  manifest-staged hooks. The plan's literal number is a defect, not the config.
- **Files modified:** none
- **Commit:** n/a

**2. [Rule 1 - Bug] My own CONTRIBUTING prose tripped the D-11 grep**

- **Found during:** Task 2
- **Issue:** A sentence of ordinary prose named ty and pyrefly with the pathless form,
  continuing into a backticked "`src/` only". The backtick means it does not match the
  allowed `(src|tests)` continuation, so the line failed the zero-residue criterion.
- **Fix:** Rephrased to "ty and pyrefly are limited to `src/`", which carries the same
  meaning without the command-shaped token sequence. Residue grep now returns nothing.
- **Files modified:** CONTRIBUTING.md
- **Commit:** `71475d4`

  dies with this worktree. Plan 23.1-04 installs them from the main checkout.
- **No grep hook and no CI grep step** forbidding the pathless form, per D-13.
- **REQUIREMENTS.md untouched.** GATE-01/02/03 are mechanically in place but are proven
  live only by plan 23.1-04's demonstrations, and the file is shared with the other wave-1
