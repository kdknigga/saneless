**This plan deliberately does NOT install the new git shims.** Installing them from a wave-1 worktree
has two problems:
- It would put a `pre-merge-commit` shim into the shared `.git/hooks` while the other wave-1 worktrees
  still carry the old stage-less config. Their merges would then run fixers and checkers at merge time.
- The shim hard-codes the absolute path of the prek binary that installed it. A worktree `.venv`
  vanishes when the worktree is removed, and the fallback is PATH prek 0.2.30.

Plan 23.1-04 installs the shims from the main checkout, once this config is on `autodev`.

Per D-13, add NO grep hook and NO CI grep step that forbids the pathless form.

Verified facts (RESEARCH G1-G6, G10). Do not re-derive them.
- The upstream pre-commit-hooks v6.0.0 manifest declares `stages: [pre-commit, pre-push, manual]` for `check-added-large-files`, `check-executables-have-shebangs`, `end-of-file-fixer` and `trailing-whitespace`. - With `always_run: true` and `pass_filenames: false`, the full hooks run on every merge and push. They check the CHECKED-OUT working tree, not the refs being pushed (G5).
- In this clone, prek 0.3.6 refuses a plain `uv run prek install` (exit 2, because `core.hooksPath` is set locally). The working form is `uv run prek install --git-dir "$(git rev-parse --path-format=absolute --git-common-dir)"`. Do NOT upgrade prek.
- githooks(5): `git merge --no-verify` skips pre-merge-commit, and `git push --no-verify` skips pre-push. A conflicted merge that is finished with `git commit` fires pre-commit, not pre-merge-commit (D-05).
- A rejected pre-merge-commit leaves MERGE_HEAD, MERGE_MSG and a staged merge result behind. Recover with `git merge --abort`, never with `git commit` (RESEARCH Pitfall 3).
- No tracked `.py` exists outside `src/` and `tests/`, so CI's path change loses no coverage (G6).
</interfaces>
