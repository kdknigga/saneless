# Phase 23.1: Dark Mode and the Commit Gate - Context

**Gathered:** 2026-09-11
**Status:** Ready for planning

<domain>
## Phase Boundary

Two defects that Phase 23 execution exposed are closed:

1. **Dark mode never engages.** `src/saneless/web/templates/base.html:2` sets `data-theme="auto"`,
   which Pico v2 does not recognise, so every user has seen the light palette since Phase 12. After
   this phase the UI renders Pico v2.1.1's dark palette under `prefers-color-scheme: dark`, and
   `.status-done`, `.status-error` and `.status-fallback` all measure at least 4.5:1 in both schemes.
   Requirements **DARK-01, DARK-02, DARK-03**. The design contract is already written and approved:
   `23.1-UI-SPEC.md`.
2. **A TDD RED commit is impossible.** `.pre-commit-config.yaml` runs `uv run ty check` and
   `uv run pyrefly check src tests` on every commit. Both reject a test file that references a
   symbol that does not exist yet, so all eight Phase 23 executors had to fold RED and GREEN into
   one commit. After this phase a RED commit passes with hooks enabled and no suppression, a type
   error still cannot reach `master`, and no verification command anywhere uses bare
   `uv run pyrefly check`. Requirements **GATE-01, GATE-02, GATE-03**.

`workflow.tdd_mode` is `true`, so GATE-01 affects every phase from 24 to 32. That is why this
phase was inserted rather than left for the end of the milestone.

**Not in this phase:** vendoring Pico or htmx locally, SRI hashes, and a CI browser-test job (all
ROBU-09 / ROBU-11, Phase 26); any change to `release.yml` or `docs.yml` (Phase 31).

</domain>

<decisions>
## Implementation Decisions

All decisions below are **locked for planning**. Two diverge from the option recommended during
discussion (**D-11** and **D-13**); both are called out where they appear.

### Where the type checkers run (GATE-01)

- **D-01: At the `pre-commit` stage, ty and pyrefly check `src` only.** The commit-stage hooks run
  `uv run ty check src` and `uv run pyrefly check src`. A RED test file's errors (unresolved import,
  unknown attribute) live in `tests/`, which the commit stage no longer checks, so the commit passes.
  A type error in `src/` is still rejected on every commit.
- **D-02: The full check runs at the `pre-merge-commit` and `pre-push` stages.** Those hooks run
  today's full commands: `uv run ty check` and `uv run pyrefly check src tests`.
  - Why `pre-merge-commit` matters here: GSD lands every executor worktree in `autodev` with
    `git merge "$WT_BRANCH" --no-ff` (`~/.claude/get-shit-done/workflows/execute-phase.md:787`,
    confirmed in `git log --merges`). A `--no-ff` merge that commits by itself fires
    `pre-merge-commit` (githooks(5): a non-zero exit aborts the merge before the commit is
    created). So every worktree is fully type-checked as it lands, **in the main checkout**, where
    pyrefly's ignore-file problem cannot occur.
  - Why `pre-push` alone was rejected: executors commit and merge locally and never push, and
    `autodev` runs about 94 commits ahead of `master`. A pre-push-only gate would leave nothing
    local between commits.
- **D-03: The extra hook shims are declared in config, not installed by hand.** Add
  `default_install_hook_types: [pre-commit, pre-merge-commit, pre-push]` to
  `.pre-commit-config.yaml` and re-run `uv run prek install` in this clone. Worktrees share the
  shims (`core.hooksPath` is `.git/hooks`). prek 0.3.6 supports both hook types (verified via
  `prek install --help`), and git is 2.47.3 (the hook needs ≥ 2.24).
- **D-04: CI stays the enforcing boundary for `master`, unchanged in kind.** The `master gate`
  ruleset (id 22777879) requires the `lint` and `test` checks and blocks non-fast-forward pushes.
  `lint` already runs both type checkers over the whole project. The only CI edit is D-11's pyrefly
  path arguments.
- **D-05: A conflicted worktree merge gets only the commit-stage check. Accepted, and documented.**
  A merge with conflicts is finished with a plain `git commit`, which fires `pre-commit`, not
  `pre-merge-commit`, so it gets the `src`-only check. That is rare. A `tests/` type error in that
  situation is still caught at pre-push, in CI, and by the GSD verifier's full check.
  `CONTRIBUTING.md` says so. Rejected: a custom hook script that detects `MERGE_HEAD` and switches to
  the full check.
- **D-06: GATE-01 is met literally: no suppression of any kind.** A RED commit must pass every
  *other* hook as-is (ruff, ruff-format, check-ast and the rest), so the RED test file must be
  ruff-clean. None of these is part of the mechanism: `--no-verify`, `SKIP=`, `# type: ignore`,
  `# noqa`, disabling a rule, or a `raise NotImplementedError` stub that makes the symbol exist. That
  stub was the Phase 23 workaround recorded in ICM, and it no longer has a reason to exist.

### Proving the gate (GATE-01, GATE-02; roadmap criteria 3 and 4)

- **D-07: Local demonstrations only, recorded with observed output in the SUMMARY.** Following
  Phase 20's D-08..D-10 rule, test what is genuinely uncertain, which is this repo's hook
  configuration, not each tool's exit codes:
  1. On a throwaway branch, **commit a real RED test** (a `tests/` file that imports a symbol that
     does not exist) with hooks enabled. It must succeed. Also commit one deliberate type error in
     `src/`. It must be rejected, which proves the `src`-only stage still guards `src`.
  2. **`git merge --no-ff`** a branch whose `tests/` carries a deliberate type error. The
     `pre-merge-commit` stage must reject it and the merge must not commit.
  3. **Push** a branch with a `tests/` type error at its tip to a **local bare repository** (in the
     scratchpad, never `origin`). The `pre-push` stage must reject it.

  Throwaway branches and the bare repo are removed afterwards.
- **D-08: No CI rerun and no seeded-break PR.** The claim that a type error cannot reach `master`
  rests on Phase 20's proof that a `lint` failure goes red and blocks `master`, plus two read-backs:
  `ci.yml`'s `lint` job still runs both checkers (with D-11's paths), and the ruleset still requires
  `lint`. A seeded-break PR was rejected because it costs a D-22 filtered-branch push for no new
  information.
- **D-09: No automated regression test for the hook configuration.** A pytest that builds a temp
  repo and drives prek, git, ty and pyrefly was rejected as slow and fragile, and it would pull the
  toolchain into the suite.

### Bare `pyrefly check` (GATE-03)

- **D-10: Why it matters, recorded once where plan authors will see it.** Inside a gitignored
  directory, such as a `.claude/worktrees/` git worktree, pyrefly's `use-ignore-files` default
  filters out every source file, and bare `uv run pyrefly check` can report success having checked
  nothing. Phase 23 saw it exit 1 in some worktrees and 0 in others. Naming paths bypasses the
  filter. This reason goes in `CLAUDE.md` (Commands and Gotchas), `CONTRIBUTING.md`, and stays in
  the existing comment in `.pre-commit-config.yaml`.
- **D-11: Every occurrence is rewritten, literally, including historical records.**
  **DIVERGES from the recommendation**, which was to fix live guidance only. The user chose the
  literal reading of GATE-03. Rewrite every bare `pyrefly check` command to
  `uv run pyrefly check src tests` in:
  - `CLAUDE.md` (line 17), `CONTRIBUTING.md` (lines 45 and 54), `.github/workflows/ci.yml:32`;
  - every file under `.planning/`: `codebase/CONCERNS.md`, `research/STACK.md`,
    `reviews/2026-09-09-code-review.md`, `quick/260320-j26-*`, all of `phases/20-*` through
    `phases/23-*`, and the whole v1.0 archive under `milestones/v1.0-phases/`. That is about 180
    lines in total; the measured per-file counts are in the discussion log's source grep.

  **Exception:** text that quotes the bare form *as the thing forbidden* is not a verification
  command and stays. That covers REQUIREMENTS.md GATE-03, ROADMAP criterion 5, this CONTEXT.md, the
  DISCUSSION-LOG, and any 23.1 plan or summary that describes the rule. Verification: the grep
  `grep -rnE "pyrefly check" .planning CLAUDE.md CONTRIBUTING.md .github .pre-commit-config.yaml | grep -vE "pyrefly check (src|tests)"`
  must return **only** those quoting lines, each listed and justified in the SUMMARY.
  The commit-stage hook's `pyrefly check src` (D-01) names a path, so it is not bare.
  `.planning/` is stripped from every push (Phase 20 D-22), so this rewrite stays local.
- **D-12: CI's pyrefly step becomes `uv run pyrefly check src tests`.** CI's checkout is not inside
  a gitignored directory, so the bare form worked there. It changes anyway because criterion 5
  covers CI, and so CI and the hooks run identical commands.
- **D-13: No guard against it creeping back.** **DIVERGES from the recommendation**, which was a
  pygrep prek hook. The user chose to rewrite once and rely on the written reason in D-10. Do not
  add a grep hook or a CI grep step.

### Dark mode (DARK-01, DARK-02, DARK-03)

- **D-14: `23.1-UI-SPEC.md` is the locked design contract and is not re-litigated.** In summary:
  delete `data-theme` from `<html>`; add `<meta name="color-scheme" content="light dark">`; pin Pico
  to `@picocss/pico@2.1.1`; an app-owned `--saneless-status-fallback` (`#a16207` light / `#ca8a04`
  dark) declared with selectors that mirror Pico's own; no override for `.status-done` or
  `.status-error`; `pico.colors.css` not shipped, and no `--pico-color-` reference left in
  `app.css`; computed-colour tests T1/T2/T3 with the three required mutation checks; the five edits
  to the master `.planning/UI-SPEC.md`; and the ICM correction (linking `pico.colors.css` would *not*
  have been a no-op, because `--pico-color-amber-600` is `#785800`).
- **D-15: ROADMAP criterion 1 is amended in this phase.** It currently says the test reads
  `body`'s computed background, but `body` is transparent (`rgba(0, 0, 0, 0)`) in both schemes, so
  a test written that way cannot pass. The amended text reads the root element
  (`document.documentElement`), with a one-line note explaining why. The intent is unchanged. That
  way the verifier checks the right element without needing the UI-SPEC's correction.
- **D-16: The Phase 26 coupling obligation is written into ROADMAP's Phase 26 section.** Today only
  23.1's own entry and the UI-SPEC mention it. Phase 26's section (ROBU-09) gains a short note
  pointing at `23.1-UI-SPEC.md` § "Coupling contract for Phase 26 (ROBU-09)":
  - vendor `pico.min.css` 2.1.1 only;
  - do not vendor `pico.colors.css`;
  - reintroduce no `data-theme`;
  - keep the `--saneless-status-fallback` block;
  - move the DARK browser tests into CI once assets are local.

  ROBU-09's requirement text in REQUIREMENTS.md is **not** changed.
- **D-17 (carried forward, Phase 20 D-07): the DARK tests stay local-only in this phase.** They are
  `@pytest.mark.browser`, CI runs `-m "not browser"`, and they need CDN egress. Phase 26 brings
  browser tests into CI.

### Claude's Discretion

- The exact hook ids and names, and whether stage assignment uses per-hook `stages:` or a top-level
  `default_stages`.
- Whether the non-type hooks (ruff, ruff-format, the pre-commit-hooks fixers, `sync-with-uv`) also
  run at `pre-merge-commit` and `pre-push`. **The researcher must check this first:** in pre-commit
  semantics a hook with no `stages:` runs at **every installed hook type**. Once D-03 installs two
  more shims, file-modifying hooks (`ruff --fix`, `end-of-file-fixer`, `trailing-whitespace`,
  `mixed-line-ending --fix`, `pretty-format-json`, `sync-with-uv`) would start running at merge and
  push time, where modifying files fails the operation. Most likely `default_stages: [pre-commit]`,
  with the two full type-check hooks opting into `[pre-merge-commit, pre-push]`, but confirm against
  prek 0.3.6's actual behaviour.
- Whether the full ty check stays bare `uv run ty check` (project root, as the hook runs today; ty
  was unaffected by the worktree problem) or becomes `uv run ty check src tests` for symmetry.
- The prose and structure of the `CONTRIBUTING.md` and `CLAUDE.md` updates, within D-05 and D-10.
  `CONTRIBUTING.md`'s "`--no-verify` no longer skips the gate" section must stay true.
- How the D-07 demonstrations are scripted, and how the bare repo and throwaway branches are
  cleaned up.
- The mechanism for the D-15 and D-16 ROADMAP edits: use a `gsd-sdk query` roadmap handler if one
  covers free-text amendments, otherwise a careful targeted edit.
- The rewrite in D-11 is mechanical. Prose that names the tool without being a command (for
  example, "pyrefly check passes clean") gets the path arguments too, so that the D-11 grep comes
  back clean except for the quoting lines.

<specifics>
## Specific Ideas

- The gate design turned on one observation: GSD's `--no-ff` worktree merge fires
  `pre-merge-commit`. That lets RED commits flow freely inside a worktree while every worktree is
  still fully type-checked as it lands, which keeps local protection close to what it is today
  without any suppression.
- The user applied the standing verification-rigor rule. The proof is three local demonstrations
  of this repo's hook configuration, not a re-proof that CI or the type checkers work.
- Two choices went against the recommendation, knowingly: rewrite *all* bare `pyrefly check`
  occurrences, including historical records (D-11), and add *no* guard (D-13).

</specifics>
