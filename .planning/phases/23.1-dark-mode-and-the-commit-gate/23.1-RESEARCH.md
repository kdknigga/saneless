#### Where the type checkers run (GATE-01)

- **D-01: At the `pre-commit` stage, ty and pyrefly check `src` only.** The commit-stage hooks run
  `uv run ty check src` and `uv run pyrefly check src`. A RED test file's errors (unresolved import,
  unknown attribute) live in `tests/`, which the commit stage no longer checks, so the commit passes.
  A type error in `src/` is still rejected on every commit.
- **D-02: The full check runs at the `pre-merge-commit` and `pre-push` stages.** Those hooks run
  today's full commands: `uv run ty check` and `uv run pyrefly check src tests`.
  - Why `pre-merge-commit` matters here: GSD lands every executor worktree in `autodev` with
    `git merge "$WT_BRANCH" --no-ff` (`~/.claude/get-shit-done/workflows/execute-phase.md:787`,
    confirmed in `git log --merges`). A `--no-ff` merge that commits by itself fires
    `pre-merge-commit` (githooks(5): a non-zero exit aborts the merge before the commit is
    created). So every worktree is fully type-checked as it lands, **in the main checkout**, where
    pyrefly's ignore-file problem cannot occur.
  - Why `pre-push` alone was rejected: executors commit and merge locally and never push, and
    `autodev` runs about 94 commits ahead of `master`. A pre-push-only gate would leave nothing
    local between commits.
- **D-03: The extra hook shims are declared in config, not installed by hand.** Add
  `default_install_hook_types: [pre-commit, pre-merge-commit, pre-push]` to
  `.pre-commit-config.yaml` and re-run `uv run prek install` in this clone. Worktrees share the
  shims (`core.hooksPath` is `.git/hooks`). prek 0.3.6 supports both hook types (verified via
  `prek install --help`), and git is 2.47.3 (the hook needs ≥ 2.24).
- **D-04: CI stays the enforcing boundary for `master`, unchanged in kind.** The `master gate`
  ruleset (id 22777879) requires the `lint` and `test` checks and blocks non-fast-forward pushes.
  `lint` already runs both type checkers over the whole project. The only CI edit is D-11's pyrefly
  path arguments.
- **D-05: A conflicted worktree merge gets only the commit-stage check. Accepted, and documented.**
  A merge with conflicts is finished with a plain `git commit`, which fires `pre-commit`, not
  `pre-merge-commit`, so it gets the `src`-only check. That is rare. A `tests/` type error in that
  situation is still caught at pre-push, in CI, and by the GSD verifier's full check.
  `CONTRIBUTING.md` says so. Rejected: a custom hook script that detects `MERGE_HEAD` and switches to
  the full check.
- **D-06: GATE-01 is met literally: no suppression of any kind.** A RED commit must pass every
  *other* hook as-is (ruff, ruff-format, check-ast and the rest), so the RED test file must be
  ruff-clean. None of these is part of the mechanism: `--no-verify`, `SKIP=`, `# type: ignore`,
  `# noqa`, disabling a rule, or a `raise NotImplementedError` stub that makes the symbol exist. That
  stub was the Phase 23 workaround recorded in ICM, and it no longer has a reason to exist.

## Summary

The DARK half has already been measured and is contract-locked by `23.1-UI-SPEC.md`. It needs four things: a one-attribute template fix, a CDN pin and a meta tag, an 18-line CSS block, and three parametrised Playwright tests that reuse existing fixtures. There is one planning subtlety. The T1–T3 tests are type-clean and fail only at run time, so a DARK RED commit works under today's hooks. The DARK plan therefore does not have to wait for the gate fix.

The GATE half had real unknowns. Resolving them turned up three facts that contradict what CONTEXT.md assumed:

1. **`default_stages: [pre-commit]` is not enough.** The upstream `pre-commit-hooks` v6.0.0 manifest declares its own `stages: [pre-commit, pre-push, manual]` for four hooks: `check-added-large-files`, `check-executables-have-shebangs`, `end-of-file-fixer` and `trailing-whitespace`. A top-level `default_stages` does not override a manifest's declared stages. Two of those four modify files, and they would still run at pre-push. Each of the four needs a per-hook `stages: [pre-commit]`. With that config (config B below), exactly the two full type-check hooks run at pre-merge-commit and pre-push. This was observed, not inferred.
2. **`uv run prek install` fails in this clone.** prek 0.3.6 exits 2 with "Cowardly refusing to install hooks with `core.hooksPath` set", and this repo sets `core.hooksPath` locally. D-03's literal command will fail. What works in 0.3.6 is `uv run prek install --git-dir "$(git rev-parse --path-format=absolute --git-common-dir)"`. It installs all three shims from `default_install_hook_types` and overwrites the existing prek shim. prek ≥ 0.3.9 honours repo-local `core.hooksPath` ([prek changelog 0.3.9, #1892](https://github.com/j178/prek/pull/1892)); that is an alternative, not the recommendation.
3. **pre-push checks the working tree, not the commits being pushed.** The type-check hooks use `always_run: true` and `pass_filenames: false`, so they check whatever is checked out. Pushing a broken branch that is *not* checked out passed. D-07 demo 3 must therefore push `HEAD` from a checkout whose tree carries the error, and the docs must not overclaim what pre-push inspects.

**Primary recommendation:** use config B, with per-hook `stages: [pre-commit]` on the four manifest-staged hooks and on nothing else. Install with the `--git-dir` form. Run the D-07 demonstrations inside a throwaway `git worktree` of the real repo, placed in the scratchpad; it shares the real shims through `core.hooksPath`. Merge only between throwaway branches, never into `autodev`.

## Key Findings (GATE)

### G1. Stage semantics in prek 0.3.6 — observed with `prek run --stage <s> --all-files --dry-run`

| Config | pre-commit | pre-merge-commit | pre-push |
|--------|-----------|------------------|----------|
| **Current** (no `stages:` anywhere) | all 25 | 21 hooks, including `ruff --fix`, `mixed-line-ending --fix`, `pretty-format-json`, `sync-with-uv`, both type checkers | all 25 |
| **A**: `default_stages: [pre-commit]` + full hooks `stages: [pre-merge-commit, pre-push]` | all 25 (with src-only type checks) | only the 2 full type checks | **6**: `check-added-large-files`, `check-executables-have-shebangs`, `end-of-file-fixer`, `trailing-whitespace` + 2 full checks |
| **B**: A + per-hook `stages: [pre-commit]` on those four | all 25 (with src-only type checks) | only the 2 full type checks | only the 2 full type checks |

Why A leaks: the four hooks' upstream manifest declares `stages: [pre-commit, pre-push, manual]`. That is why they were already absent from pre-merge-commit in the current config. prek's docs define `default_stages` as the stages used "when a hook does not specify its own" ([prek configuration reference](https://github.com/j178/prek/blob/master/docs/reference/configuration.md)). A manifest-declared value counts as specifying its own, and a per-hook `stages:` in the project config overrides the manifest. [VERIFIED: dry-run A vs B, plus the cached manifest]

File-modifying hooks in the current config: `ruff --fix`, `ruff-format`, `end-of-file-fixer`, `trailing-whitespace`, `mixed-line-ending --fix=lf`, `fix-byte-order-marker`, `sync-with-uv` (it rewrites `.pre-commit-config.yaml` revs) and `sort-simple-yaml`. `pretty-format-json` without `--autofix` fails rather than rewriting. Under config B none of them runs at merge or push.

### G2. prek input per stage, and `always_run` hooks

Per prek's stage table ([configuration reference](https://github.com/j178/prek/blob/master/docs/reference/configuration.md)): pre-merge-commit receives "repository file paths from the staged merge result", and pre-push receives "repository file paths changed in the push range". With `always_run: true` and `pass_filenames: false`, the two full hooks ran in every observed case:
- a merge that touched only `docs_demo_clean.md`;
- a push of a new branch;
- a push of an update range;
- `prek run --stage pre-push` and `prek run --stage pre-merge-commit` with nothing staged (both exit 0 on a clean tree).

### G3. `prek install` and `core.hooksPath` (blocks D-03 as written)

- This repo sets `core.hooksPath` = `/home/kris/git/saneless/.git/hooks`, scope **local** (`.git/config`). There is no global value. [VERIFIED: `git config --show-origin --show-scope`]
- The existing `.git/hooks/pre-commit` is a prek shim ("File generated by prek", `--script-version 4`) dated 2026-03-20. No `.legacy` file exists.
- prek 0.3.6, with a local hooksPath set:

  | Command | Result |
  |---|---|
  | `uv run prek install` | **exit 2**, "Cowardly refusing to install hooks with `core.hooksPath` set" |
  | `uv run prek install --git-dir "$(git rev-parse --path-format=absolute --git-common-dir)"` | exit 0; installs **every** type in `default_install_hook_types` (`pre-commit`, `pre-merge-commit`, `pre-push`); silently overwrites existing prek shims; idempotent on re-run |

  [VERIFIED: demo2/test3 logs]
- Use `--git-common-dir`, not `--absolute-git-dir`. From a worktree, the latter resolves to `.git/worktrees/<name>`, which is the wrong target. [VERIFIED]
- Shims are generic: each runs `prek hook-impl --hook-type=<type>` and reads `.pre-commit-config.yaml` from the current working tree at hook time. The pre-commit stage therefore switches to config B the moment the new config is checked out, even before re-install.
- Worktrees: a worktree created *outside* the repo (`git worktree add $SCRATCH/wt …`) still reports `core.hooksPath` = the main `.git/hooks`. Commit, merge and push hooks all fired there. [VERIFIED: test3]

### G5. What pre-push actually inspects (a D-07/GATE-02 pitfall)

In test3, a worktree was checked out at a clean `demo-base`. `git push <bare> demo-red`, whose tip carries the tests/ error, **passed**: both full checks reported Passed and the push exit code was 0. The hooks type-check the working tree, not the pushed commits. [VERIFIED]

## Common Pitfalls

### Pitfall 1: `prek install` refuses in this clone
**What goes wrong:** D-03's literal `uv run prek install` exits 2, and no new shims appear. Later demos then pass vacuously. The first scratch attempt in this research did exactly that: every demo "succeeded" with no hooks installed.
**How to avoid:** use `--git-dir "$(git rev-parse --path-format=absolute --git-common-dir)"`, then check that `ls .git/hooks` lists all three shims **before** any demo.
**Warning signs:** an install exit code other than 0, or a demo commit that prints no hook lines.

### Pitfall 2: file-modifying hooks at push time
**What goes wrong:** with `default_stages` alone, `end-of-file-fixer` and `trailing-whitespace` still run at pre-push. If either rewrites a file, the push fails with a dirty tree.
**How to avoid:** config B. Verify with `uv run prek run --stage pre-push --all-files --dry-run`, which must list exactly the two `(full)` hooks, and with `--stage pre-merge-commit`, which must list the same two.

### Pitfall 3: a rejected pre-merge-commit leaves the merge half-done
**What goes wrong:** the merge exits 1 but leaves MERGE_HEAD, MERGE_MSG and a staged merge result behind. GSD's loop (`execute-phase.md:787-792`) treats any merge failure as "⚠ Merge conflict … resolve manually" and `break`s, so the message misnames the cause.
**How to avoid:** document the recovery in CONTRIBUTING and the SUMMARY:
1. Read the hook output.
2. `git merge --abort`.
3. Fix the type error on the worktree branch.
4. Re-merge.

Do not finish the merge with `git commit`. That fires only the src-only commit hooks, which is the D-05 path, and would let the tests/ error through.

### Pitfall 4: ROADMAP edits lost after a worktree merge
**What goes wrong:** the D-15/D-16 edits, made in an executor worktree, get overwritten by the orchestrator's post-merge `cp "$ROADMAP_BACKUP" .planning/ROADMAP.md`.
**How to avoid:** put the ROADMAP edits where the orchestrator will not revert them. One way is a plan the orchestrator runs sequentially in the main checkout, if the workflow allows it. Otherwise, verify after the phase merges with `grep -n 'document.documentElement' .planning/ROADMAP.md` and `grep -n 'Coupling contract for Phase 26' .planning/ROADMAP.md`, and re-apply if they are missing. The verifier should run those two greps.

### Pitfall 5: the pre-push demo proves nothing
**What goes wrong:** `git push <bare> demo-red` while a clean branch is checked out passes (G5).
**How to avoid:** push `HEAD` from the checkout that carries the error: `git push "$BARE" HEAD:refs/heads/demo-red`. Afterwards, confirm with `git --git-dir="$BARE" branch -a` that the branch was not created.

### Pitfall 6: the D-11 grep self-matches in new 23.1 artefacts
**What goes wrong:** every PLAN or SUMMARY that quotes the D-11 grep verbatim, or names the pathless form, adds another quoting line to justify.
**How to avoid:** in new 23.1 artefacts, spell greps `pyrefly[[:space:]]check` and describe the defect as "the pathless form". List whatever quoting lines remain.

### Pitfall 7: T2 probe races
**What goes wrong:** you might expect the 1 s htmx poll on `#status-area` to swap out an appended probe.
**Why it doesn't:** on the idle page `#status-area` has no `hx-trigger` (`partials/status.html:1-6`, which renders polling only when `job.is_active`), and `#history-body` is server-rendered via `index.html:80`. A probe appended, read and removed inside one synchronous `page.evaluate` cannot interleave with an htmx swap anyway. Keep all three steps in one evaluate.

### Pitfall 8: worktree git commands rewritten by rtk
**What goes wrong:** inside `isolation=worktree` agents, the rtk hook rewrites `git add`/`commit`/`status`/`log`/`diff`, and the worktree guard refuses the rewritten command (ICM `01M28M409W8TMXMNV0MQ7EK9NG`).
**How to avoid:** demo scripts and executor commands use `/usr/bin/git`. Hooks still run: that bypass skips rtk, not git hooks.

### WCAG helper shape (T2)

```python
# Source: 23.1-UI-SPEC § T2 (formula), WCAG 2.x relative luminance
def _relative_luminance(css_colour: str) -> float:
    """Return the WCAG relative luminance of an ``rgb()``/``rgba()`` string."""
    inner = css_colour[css_colour.index("(") + 1 : css_colour.index(")")]
    channels = [float(part) / 255 for part in inner.split(",")[:3]]
    linear = [c / 12.92 if c <= 0.04045 else ((c + 0.055) / 1.055) ** 2.4 for c in channels]
    return 0.2126 * linear[0] + 0.7152 * linear[1] + 0.0722 * linear[2]
```

The ratio is `(max(L1, L2) + 0.05) / (min(L1, L2) + 0.05)`. The executor must run ruff and both type checkers on the final helper.
