## Fixed Issues

### WR-03: The documented local pre-flight checks almost nothing

**Files modified:** `CONTRIBUTING.md`, `CLAUDE.md`
**Commit:** `461315b`
**Applied fix:** Switched both files to `uv run prek run --all-files`, including
the `--stage pre-push` form, and explained why it is not optional: prek's default
scope is the *staged* set, and before a push nothing is staged, so 23 of 25 hooks
were skipped. Kept the bare form documented only for the case where the staged set
is the point. Added a matching gotcha line to `CLAUDE.md`.

### WR-04: Read-only hooks were silenced at merge and push as collateral

**Files modified:** `.pre-commit-config.yaml`
**Commit:** `42c11f0`
**Applied fix:** Gave the eleven read-only upstream hooks an explicit
`stages: [pre-commit, pre-merge-commit, pre-push]`, and added non-mutating
`ruff check --no-fix .` and `ruff format --check .` hooks scoped to merge and push.
Verified empirically with `prek run --stage pre-push --all-files`: fifteen hooks now
run there and no file-modifying hook is among them.

### WR-05: `test_pico_css_applied` asserts nothing and hides the suite's CDN dependency

**Files modified:** `tests/test_browser.py`
**Commit:** `b574d80`
**Applied fix:** **Adapted — the review's suggested fix was itself vacuous.** The
review proposed `assert box["x"] > 0`. Measured against a Playwright route-abort on
`cdn.jsdelivr.net`:

| state | x | width |
|---|---|---|
| PicoCSS loaded | 40 | 1200 |
| CDN blocked (unstyled) | 8 | 1264 |

`x > 0` passes unstyled too, because `<body>` carries a default 8px margin. Pico's
`.container` *width cap* is what discriminates, so the committed assertion checks the
cap and keeps a left-inset check above the 8px default. Proved the committed predicate
PASSES styled and FAILS with the CDN blocked. Module docstring now names this test as
the diagnosis for a mass colour failure.

### WR-06: `fallback_page` teardown does not restore the idle state it claims to

**Files modified:** `src/saneless/job.py`, `tests/test_job.py`, `tests/test_browser.py`
**Commit:** `5380d98`
**Applied fix:** Took the review's "better" option. Added `JobStore.delete_job(job_id)`
— serialised with `@_locked` like every other writer, with a `_DELETE_BY_ID` statement
constant alongside its peers — because the store had no deletion API outside `prune()`,
which deletes by age and row count and is the wrong shape for a caller holding one id.
The teardown now deletes the row instead of only unsetting the pointer, so the
`list_recent(limit=1)` fallback in `index()` and `current_job_status()` no longer drags
the FALLBACK page onto every later test. Corrected the `_goto` comment to state what the
idle page really renders and why that now holds. Added two unit tests; the existing
reflective lock-coverage and no-public-self-call tests accept the new method.

### WR-07: The fixture bypasses `JobStore`'s public API and its lock, on a stale premise

**Files modified:** `tests/test_browser.py`
**Commit:** `59ac838`
**Applied fix:** Replaced the raw `job_store._conn` UPDATE (and the separate
`update_state` call) with one `finish_job(..., result=JobResult(...))` — the public
writer for the `warning` column, which the worker already uses. Recorded why the
workaround was unsafe: the test thread opened a transaction on the shared connection
holding none of the store's lock, and sqlite3 connection context managers do not nest.

### WR-08: The contrast probe treats any translucent background as opaque

**Files modified:** `tests/test_browser.py`
**Commit:** `f7c8e18`
**Applied fix:** The JS probe now returns the whole stack of painted layers out to the
first fully opaque one, and a new `_flatten` composites it in Python. `_parse_rgba`
replaces the inline slice and asserts on anything that is not `rgb()`/`rgba()`, so a
browser returning `color(srgb ...)` names the string instead of raising `ValueError`
from `str.index`. Three new helper tests cover the compositing and the rejection path;
they need no browser, so unlike the probe itself they run in CI.

### WR-09: Four hard-coded palette constants with nothing tracking their source

**Partial by design.** WR-09 opens "Fix CR-01 first, so the pin is at least enforced."
