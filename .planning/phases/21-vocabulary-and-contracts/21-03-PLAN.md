<objective>
Delete the web layer's three private copies of the job vocabulary and re-back the templates
on the shared module.

Purpose: `web/app.py` holds a fourth label map keyed by raw `str` with a silent
raw-value fallthrough; `status.html` re-spells the CLI's progress prose as an `if/elif`
chain over string literals; `index.html` carries two more hand-written state lists that are
not even the same list. Templates are the ONE surface no type checker guards, so every
literal left behind will drift silently forever.

Output: `web/app.py` with two filters and one global backed by `vocabulary.py`, three
templates with zero state-name literals, and the D-10 test replacement.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Python value -> Jinja render -> browser | Label strings and `job.error` are interpolated into HTML served to the LAN |
| Status poll -> htmx swap | The status partial is re-fetched every second; a render failure becomes a bare HTTP 500 |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-21-02 | Tampering | XSS via a label reaching `history.html` / `status.html` | mitigate | Every label is a developer-authored constant from `vocabulary.py`, never user input, and Jinja2Templates autoescapes `.html`. Concrete control: NO `\| safe` filter on any label — enforced by a grep gate in Task 2's acceptance criteria |
| T-21-05 | Denial of service | A raising label filter freezing the status area | mitigate | A filter that raises inside a render propagates out of `TemplateResponse` and Starlette returns a bare 500; htmx 2 does not swap non-2xx bodies, so the UI would freeze silently while the 1s poll hammers the server. The mitigation already exists at the store boundary — `JobState(row[3])` at `job.py:187`/`:262` rejects any unknown value before a `Job` is constructed — and this plan does not weaken it |
| T-21-06 | Information disclosure | Raw exception text shown to family members via `{{ job.error }}` | accept | PRE-EXISTING and deliberately unchanged. D-12 defers plain-language error display to Phase 30 (U-05), which depends on Phase 24 making the underlying messages truthful. Substituting a generic message now would replace specific text with something vaguer and is a regression, not a fix. Net change in this plan: zero |
| T-21-SC | Tampering | Supply chain — package installs | mitigate | This plan installs NOTHING. No dependency, no `uv.lock` change; only Jinja filter/global registration on an already-pinned Jinja2 3.1.6 |
</threat_model>
