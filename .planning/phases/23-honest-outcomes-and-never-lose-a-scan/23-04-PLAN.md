<objective>
Make the paperless-ngx client tell the truth about what happened: reach a terminal task status
against the wire format the server actually speaks, raise instead of returning sentinels, honour the
documented timeout on a real clock, distinguish five connection outcomes, and hand a whole file to
the consume directory rather than a half-written one.

Purpose: OUTC-11 (D-17), OUTC-07 (D-12), OUTC-08 (D-13), OUTC-01's raise half (D-01, D-11), and
OUTC-05's atomic-rename half (D-09).

**Sequencing note, and the reason this plan is wave 2 rather than later.** `poll_task` was written
against API v9 while paperless-ngx serves v10 to a header-less client, so `isinstance(tasks, list)`
is `False` and no terminal status is ever observed. That is invisible today only because
`pipeline.py:523` discards the return value. The moment timeouts raise and the PDF is preserved on
timeout (plan 23-06 / D-10), every *successful* scan would record FAILED with a stray file in
`failed/` — the exact inversion of this phase's goal. Task 1 therefore lands the shape tolerance and
the raise semantics **in one task**, and this plan lands before 23-06. Do not split Task 1.

Output: a `paperless.py` whose return values and exceptions mean what they say.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-15 | Spoofing | unpinned API version negotiation | mitigate | With no `Accept` header the client silently receives whatever the server's configured default is — today v10, one day v11 — and misparses it. Pinning `Accept: application/json; version=9` makes the contract explicit, and `_extract_task` tolerating both shapes means the client keeps working if v9 support is eventually dropped. Both halves are required; either alone leaves a failure mode open. |
| T-23-16 | Information Disclosure | the non-200 poll error message interpolating `response.text` | mitigate | The message lands in `job.error`, which `status.html` renders. A hostile or misconfigured upstream could return a multi-megabyte body, an HTML error page echoing request headers, or content designed to flood the status area. Control: truncate the interpolated body to 500 characters with an explicit marker, and interpolate only the status code and that truncated body — never request headers, never the client's own base URL (which embeds no token today, but `upload_document`'s existing `exc.response.text` interpolation at `:182-186` shows how easily that changes). Jinja2 autoescaping is a second layer, verified in plan 23-05. CFG-05 in Phase 27 makes the token a `SecretStr`; this plan's obligation is to add no NEW path for it. |
| T-23-17 | Denial of Service | unbounded poll wall clock | mitigate | `elapsed` accumulated sleep time only, so with a 30 s per-request `httpx` timeout the real ceiling was roughly `timeout + 30 * polls` — unbounded relative to the documented 300 s, and it blocks the single worker thread for the whole time. `time.monotonic()` deadline plus `time.sleep(min(delay, remaining))` bounds it at the configured value. A monotonic clock also cannot be moved by an NTP step or a manual clock change. |
| T-23-18 | Denial of Service | a revoked token or moved endpoint burning the full timeout | mitigate | D-12: any non-200 raises on the first poll, so a 401 is reported as a 401 in under a second instead of as a 300-second timeout.
