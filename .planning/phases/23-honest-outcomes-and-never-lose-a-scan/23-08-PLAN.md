  <behavior>
    Five parametrised cases, each asserting the persisted job row, not a mock call list:

    - **SUCCESS** — transport returns a task UUID from `post_document` and a terminal success from
      `/api/tasks/`. Asserts `state is JobState.DONE`, `outcome is ScanOutcome.SUCCESS`,
      `warning is None`, the three page counts match the stub scanner's page count, and
      `failed_dir` either does not exist or is empty.
    - **Paperless FAILURE** — transport returns a terminal failure carrying a message. Asserts
      `state is JobState.ERROR`, `outcome is None` (D-01: failures raise, the column stays NULL),
      the Paperless message appears in `job.error`, all three page counts are `None`,
      `failed_dir` contains exactly one `.pdf`, and that file's name appears in `job.error`.
    - **TIMEOUT** — transport returns a 200 with an empty task list forever. Asserts
      `state is JobState.ERROR`, `outcome is None`, the task id appears in `job.error`,
      `failed_dir` contains exactly one `.pdf` (D-10: preserve on timeout too), and that the case
      completed in well under a second of wall clock.
    - **Consume-directory fallback** — transport returns 500 for `post_document` on every attempt
      while `consume_dir` is configured. Asserts `state is JobState.FALLBACK`,
      `outcome is ScanOutcome.FALLBACK`, `warning` is not `None`, the three page counts are
      populated, `consume_dir` contains exactly one `.pdf` and no hidden staging file, and
      `failed_dir` is empty — nothing failed, so nothing is preserved.
    - **Duplex mismatch** — a profile whose `source` is `"Manual Duplex"` and a scanner stub
      returning an odd split across the two passes, with a successful transport. Asserts
      `state is JobState.DONE`, `outcome is ScanOutcome.SUCCESS`, `warning` is not `None` and
      describes the mismatch, and the page counts are populated.

    Plus, in every case: at least one v10-shaped `/api/tasks/` response somewhere in the
    parametrisation, so the e2e layer exercises the pagination tolerance and not only the unit layer.
  </behavior>
  <action>
    Create `tests/test_outcomes_e2e.py` with a module docstring stating what makes this file
    different: it is the only test that runs the real `run_pipeline` through the real `ScanWorker`,
    stubbing exactly two things — the scanner and the HTTP transport — and nothing else.

    **Structure (this is the discretionary part; record the choice in the summary).** One
    `@pytest.mark.parametrize` over a list of small frozen case dataclasses, each carrying a label, a
    transport handler factory, a profile-source override, a page-count plan, and the expected
    terminal assertions. One test method that builds the world from the case, runs it, and asserts.
    A dataclass beats a tuple here because five heterogeneous cases with eight fields each are
    unreadable as tuples, and `pytest` prints the label as the test id. Add a small number of
    targeted extra methods only where a case needs an assertion the common shape cannot express —
    prefer extending the dataclass over forking the method.

    **Do NOT monkeypatch `saneless.worker.run_pipeline`.** OUTC-10 requires the real one. Stub only:
    - the scanner: a `MagicMock(spec=ScannerBackend)` whose `scan_pages` returns an iterator of PIL
      images, exactly the `mock_scanner` fixture's shape. For the duplex case it must return
      different counts across two calls AND honour `flip_event` — read `_scan_manual_duplex`'s
      contract first; a stub that ignores the event will hang until pytest-timeout's SIGALRM rather
      than failing with a useful message.
    - the HTTP layer: `httpx.MockTransport` through `PaperlessClient(..., _transport=...)`.

    **Speed — use only seams that already exist; add none.** Measured in this repository:
    - `max_retries=1` on the `PaperlessClient` constructor removes BOTH `time.sleep(2**attempt)`
      calls in `upload_document` (measured 3.00 s at 3 retries, 1.00 s at 2, 0.00 s at 1). The
      consume-directory fallback case is the one that needs it.
    - `settings.output.paperless_task_timeout = 0.05` plus plan 23-04's
      `time.sleep(min(delay, remaining))` clamp makes the TIMEOUT case cost exactly 0.05 s instead of
      the 0.5 s the old unconditional first sleep cost.
    - The SUCCESS, FAILURE and duplex cases reach a terminal status on the first poll, before any
      sleep, and cost zero.
    Three alternatives are explicitly rejected and must not be re-proposed: monkeypatching
    `time.sleep` in `saneless.paperless` (it would disable the deadline clamp this test exists to
    exercise, and Phase 32 / M-34 owns that sweep), injecting a `sleep_fn` parameter (a production
    seam existing only for tests, for a problem two constructor parameters already solve), and making
    the backoff base configurable (same objection plus a config key with no user story).

    **Waiting for the worker.** Submit the job, then `wait_for_state(store, job.id, TERMINAL_STATES,
    timeout=2.0)` from `tests/conftest.py`, then `worker.stop()`. Do not add a flat `time.sleep` —
    `tests/test_worker.py` already has 27 of them and this file must not add a 28th. The 2 s budget
    is deliberately far below the global `timeout = 60` SIGALRM: `timeout_method = "signal"` delivers
    SIGALRM to the MAIN thread regardless of which thread is stuck, so a hang would produce a
    traceback pointing at the wait loop rather than at the stuck worker. A short budget fails with a
    useful message first. Do NOT raise the global timeout to accommodate this file.

    **Filesystem isolation.** Put `tmp_dir`, `data_dir` and `consume_dir` on three separate subtrees
    of `tmp_path`. `failed_dir` derives from `data_dir`, and placing it under `tmp_dir` would both
    confuse the assertions and trip the temp-cleanup checks the pipeline tests rely on. Use a
    file-backed `JobStore(db_path=str(settings.output.db_path))` rather than the in-memory default,
    so the test exercises the real `data_dir` path that plan 23-02 wired — and mkdir `data_dir`
    first, because `sqlite3.connect` does not create parents.

    **Strictness.** `pyproject.toml` sets `filterwarnings = ["error"]` and `xfail_strict = true`, so
    any new `DeprecationWarning` from this file fails the suite. Run it locally without `-W ignore`
    before considering it done.

    If `wait_for_state` needs a small extension (for example accepting a `frozenset` of states as
    well as a single member), make it in `tests/conftest.py` here; that is the only reason this plan
    lists `conftest.py` among its files.
