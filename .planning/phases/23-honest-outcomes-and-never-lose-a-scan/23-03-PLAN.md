<objective>
Make every assembled PDF uniquely and safely named, and make its pages declare the DPI they were
scanned at so an A4 page is an A4 page.

Purpose: OUTC-05's first half and OUTC-06, under D-09, D-18 and D-19. This is also the plan that
creates this phase's single new attack surface: a user-supplied job title becomes part of a
filesystem path for the first time in this codebase.

Output: a filename sanitiser with its own path-traversal tests, a `build_pdf_filename` composer, and
an `assemble_pdf` that takes a filename and a DPI and passes `img2pdf`'s fixed-DPI layout function.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| web form / CLI argument -> filesystem path | **This is the new one.** The job title arrives from `POST /api/scan`'s form body or a `saneless scan --title` argument and, for the first time in this codebase, becomes a path segment that is later joined against `consume_dir` and `<data_dir>/failed/`. |
| PIL images -> PDF geometry | Page pixel dimensions come from the scanner and determine MediaBox size under a fixed-DPI layout. Not attacker-controlled in any deployment this project supports. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-09 | Tampering | `sanitise_title_for_filename` — relative traversal | mitigate | A title of `../../etc/cron.d/x` must not escape `failed_dir` or `consume_dir`. The control is the `[a-z0-9]` allow-list (`re.sub(r"[^a-z0-9]+", "-")`), which removes `/`, `\` and `.` by construction rather than by enumeration. `auto_profiles._slugify` is explicitly forbidden (D-19) because it is a two-`.replace` helper that passes all three through. Enforced by a parametrised test asserting `(base / sanitised).resolve().is_relative_to(base)`. |
| T-23-10 | Tampering | `sanitise_title_for_filename` — absolute path | mitigate | `Path("/a") / "/etc/passwd"` resolves to `/etc/passwd`, so a leading `/` is a full path hijack. The same allow-list strips `/`, making an absolute segment unrepresentable. Covered by the same parametrised test with the `"/etc/passwd"` input. |
| T-23-11 | Tampering | NUL byte in title truncating a path at the C layer | mitigate | The allow-list strips `\x00`. Python's own `ValueError: embedded null byte` is a second line of defence but is deliberately not the only control — a defence that lives in someone else's library is not a control this project owns. Covered by the `"a\x00b"` test input. |
| T-23-12 | Denial of Service | name-length overflow -> `OSError: [Errno 36] File name too long` on a user-controlled path | mitigate | 60-character cap on the slug segment only; the timestamp and 8-character job-id prefix are fixed width, so the whole composed name stays well under `NAME_MAX` (255 bytes on ext4/overlayfs) and under eCryptfs's 143-byte limit. Enforced by `len(s("x" * 500)) <= 60`. |
| T-23-13 | Tampering | filename collision overwriting a previously preserved scan | mitigate | `shutil.move` onto an explicit full destination path silently overwrites (verified in RESEARCH § Pattern 2). Uniqueness therefore has to come from the name, and it comes from the uuid4 job id rather than the timestamp — two jobs submitted in the same second with the same title would collide on timestamp alone. Enforced by the same-title/different-id distinctness test. |
| T-23-14 | Information Disclosure | job title echoed in a filename that reaches paperless as the document's original filename | accept | The title is the user's own, supplied by the same user who can read the resulting document in paperless. Making the filename reflect the title is the intended improvement — every document currently arrives as `output.pdf`. No cross-user exposure exists in this single-tenant LAN application; Phase 30 owns the owner-token work if that ever changes. |
</threat_model>
