<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| paperless-ngx -> saneless | Upstream response bodies and status codes cross into saneless classification logic. This plan defines the vocabulary that classification will produce; plan 23-04 implements the crossing. |
| saneless -> browser / CLI | `state_label`, `progress_label` and `connection_status_message` outputs are rendered to users. All three are project-authored constants, never interpolated from untrusted input. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-01 | Information Disclosure | `connection_status_message` | mitigate | All five messages are fixed literals. No status code, no response body, no URL, and no token is interpolated into the returned string — the one place a paperless error body could reach the UI via this path is closed by construction. Enforced by the parametrised test asserting each message `!= status.value`. |
| T-23-02 | Tampering | `ConnectionStatus` wire values | mitigate | `web/routes.py:128` serialises the value directly into a public JSON response and `docs/reference/web-api.md:54-56` pins three strings. The hand-written `(member, expected_wire_string)` parametrisation plus the `json.dumps` round-trip assertion are the regression control against a silent contract break. |
| T-23-03 | Elevation of Privilege | `JobState.FALLBACK` joining `TERMINAL_STATES` | mitigate | `worker.py:212-218` refuses to write any state not in `ACTIVE_STATES` from the status callback. Putting FALLBACK in `TERMINAL_STATES` (and not `ACTIVE_STATES`) means the pipeline's own status callback can never write a terminal outcome — the terminal write stays the worker's sole responsibility. The existing `(state in ACTIVE_STATES) ^ (state in TERMINAL_STATES)` partition test over `list(JobState)` is the enforcement. |
| T-23-SC | Tampering | `uv add --dev pikepdf` | mitigate | `23-RESEARCH.md` § "Package Legitimacy Audit" records `slopcheck install pikepdf` -> `[OK]`, ~9 years of releases back to 0.1.0, multi-million monthly downloads, source at github.com/pikepdf/pikepdf, and the package is already resolved in `uv.lock` at 10.5.1 as an `img2pdf` transitive dependency. Disposition is `mitigate` with no human checkpoint required: the audit is `[OK]`, not `[ASSUMED]` or `[SUS]`, and the promotion downloads no new code. |
</threat_model>
