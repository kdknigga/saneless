<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| documentation -> operator action | Documentation is a control surface for deployment security. An operator who follows a stale mount line writes durable data into ephemeral storage; one who follows a stale volume table deletes preserved scans believing them disposable. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-23-42 | Denial of Service | `docs/reference/docker.md:30` describing the data directory as "No (ephemeral OK)" | mitigate | After this phase that row applies to a directory holding the only surviving copy of failed scans. An operator pruning volumes on its authority destroys exactly what the phase exists to protect. Control: split the row so the data directory is marked **Required: Yes** and the scratch directory keeps the ephemeral marking. This is the single highest-value edit in this plan. |
| T-23-43 | Repudiation | the compose mount line duplicated in three files plus a table | mitigate | RESEARCH Pitfall 9 verified five occurrences across `docker-compose.yml`, `docs/reference/docker.md` (twice) and `docs/how-to/deploy-docker-compose.md` (twice). A partial sweep leaves the documentation instructing the exact misconfiguration OUTC-09 removes. Control: the acceptance criterion is a repository-wide `grep -rc` returning zero, not a per-file inspection. |
| T-23-44 | Information Disclosure | the upgrade note pointing users at a database file | accept | The note names the operator's own database path on their own machine, to the operator. No credential is disclosed: the job store holds titles, states and errors, not the paperless token, which lives in the config file. |
| T-23-45 | Denial of Service | unbounded `<data_dir>/failed/` growth with no documented remedy | mitigate | Plan 23-06 accepted the absence of automatic pruning (T-23-29) on the explicit condition that documentation is the mitigation. This plan discharges that condition: the growth behaviour, the correspondence between each file and a failed job, the drain procedure, and paperless-ngx's checksum duplicate detection are all stated. If this task ships without paragraph (f), T-23-29's acceptance is void. |
| T-23-46 | Tampering | an operator re-ingesting a preserved scan creating a duplicate document | mitigate | Documented rather than engineered: paperless-ngx detects duplicates by checksum on consumption, so dropping a preserved PDF back into the consume directory is safe. This is the same backstop D-10 relied on when choosing to preserve on timeout, and stating it is what makes the drain procedure actionable rather than frightening. |
