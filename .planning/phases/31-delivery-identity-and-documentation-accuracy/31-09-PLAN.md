<interfaces>
Why `v0.2.0-rc.1` is the exact spelling (all three measured):
  - `packaging.Version("0.2.0-rc.1")` normalises to `0.2.0rc1` — canonical PEP 440.
  - `uv build --wheel` with `version = "0.2.0-rc.1"` emits `saneless-0.2.0rc1-py3-none-any.whl`;
    uv_build normalises for you, so the filename PyPI sees is canonical.
  - `v0.2.0-rc.1` IS valid semver, so `docker/metadata-action`'s `type=semver` parses it.
    `v0.2.0rc1` is NOT valid semver and metadata-action would silently emit no version tag at all.

Plan 01's `test_pyproject_declares_the_0_2_0_series` accepts `^0\.2\.0(-rc\.\d+)?$` precisely so
this rehearsal does not turn the suite red for its duration. Do not weaken that regex further.

Routing: `release.yml`'s `publish-pypi` job resolves its environment with
`contains(github.ref_name, '-')` — a hyphenated tag goes to `testpypi` with
`repository-url: https://test.pypi.org/legacy/`; an unhyphenated tag goes to `pypi`. The `latest`
GHCR tag is skipped for semver pre-releases by `docker/metadata-action`'s default
`flavor: latest=auto`, because Plan 04 deleted the unconditional `type=raw,value=latest` line.

Sequencing consequence: blockers 1-3 MUST be done BEFORE the tag is pushed, or the run fails at the
publish step with an OIDC error and has to be re-tagged as `v0.2.0-rc.2` — a version number on an
index can never be reused.

Name availability re-verified 2026-09-18: both `https://pypi.org/pypi/saneless/json` and
`https://test.pypi.org/pypi/saneless/json` return 404. A pending publisher does NOT reserve the
name until first publish: if another user registers the project name first, the pending publisher
is invalidated. That is an argument for doing the rehearsal promptly.

STANDING PROJECT RULE: Claude never runs `git tag`. No task in this phase may create, push or
delete a tag.
</interfaces>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| a git tag -> an irreversible publish to a public index | Pushing a ref triggers an action whose result cannot be undone; a PyPI version number is never reusable |
| GitHub OIDC identity -> PyPI / TestPyPI / GHCR | The workflow asserts an identity bound to five exact values; a mismatch is a failed publish, a match is a real one |
| the unclaimed project name `saneless` -> any PyPI account | A pending publisher does not reserve the name |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-06 | Tampering | an accidental or premature tag push | mitigate | No task in this plan creates a tag; both tag pushes are `checkpoint:human-action` with the exact commands handed over (D-20, standing project rule). The Required-reviewers rule on the `pypi` environment means even an accidental unhyphenated tag cannot publish to real PyPI without a human click |
| T-31-21 | Tampering | the RC leaking onto real PyPI or GHCR `latest` | mitigate | Routing is structural, not conditional prose: `contains(github.ref_name, '-')` sends the hyphenated tag to the `testpypi` environment and `https://test.pypi.org/legacy/`, and the unconditional `type=raw,value=latest` line is deleted so `metadata-action`'s `latest=auto` skips `latest` for semver pre-releases. Real PyPI stays empty until the final tag, so a plain `pip install saneless` cannot resolve to the RC |
| T-31-10 | Spoofing | project-name squat between pending publisher and first publish | mitigate | Both index endpoints returned 404 on 2026-09-18 and a pending publisher does not reserve the name — if someone else registers it first the pending publisher is invalidated. The mitigation is to do the rehearsal promptly rather than defer it |
| T-31-35 | Denial of service | a burnt version number | mitigate | Blockers 1-3 are gated BEFORE the tag push, CI must be green on the exact commit to be tagged, and the wheel filename is verified locally as `saneless-0.2.0rc1-py3-none-any.whl` before the tag exists. Each check removes a way for the run to fail after the number is claimed |
| T-31-09 | Spoofing | substitution of the published RC artefacts | mitigate | `attestations: true` on the PyPI publish and `provenance: true` on the image build, both riding the workflow's OIDC identity (Plan 04) |
</threat_model>
