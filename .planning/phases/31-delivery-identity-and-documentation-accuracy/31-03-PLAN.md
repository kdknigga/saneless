<objective>
Split saneless's two operating shapes apart in logging: one-shot CLI commands keep the rotating
file handler exactly as Phase 28 wrote them; `serve` behaves as a 12-factor service and streams
to stderr with no file.

Purpose: DLVR-04. A container today writes logs into its own filesystem and throws them away on
recreation — `docker logs` shows nothing useful. The mode already selects the behaviour, so no
new config key is needed (D-24) and no Dockerfile change is needed (`CMD ["serve"]` already picks
the streaming mode).

Output: a `stream` keyword on `configure_logging`, a `stream_logs` keyword on
`_load_cli_settings`, `serve` opting in, six new tests, and the two documentation surfaces this
behaviour change falsifies corrected in the same phase.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| saneless process → log sink (stderr stream vs. rotating file) | This plan changes where records land; whoever can read the sink can read everything the loggers emit |
| third-party library loggers (httpx, uvicorn, multipart) → the same root handlers | Propagation means any level change on the root logger widens what those libraries disclose |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-31-11 | Information disclosure | `-v` in serve mode, `src/saneless/logging_config.py` | mitigate | `logging.getLogger("saneless").setLevel(DEBUG if verbose else NOTSET)` stays exactly as written and the root logger keeps the configured level, so httpx never reaches DEBUG and never prints the Paperless `Authorization` header (T-27-23, D-38). Pinned by `test_stream_mode_leaves_non_saneless_loggers_at_the_configured_level`. The stream mode adds NO new exposure — the same records, a different sink |
| T-31-18 | Information disclosure | uvicorn access log on the serve stream | accept | `access_log=True` is unchanged (D-37). Access lines carry method, path and status for a LAN appliance with no auth; they are the only per-request record and become useful once visible. No request bodies or headers are logged |
| T-31-19 | Repudiation | tracebacks discarded in serve mode | mitigate | The locked D-36 amendment puts a plain `Formatter` on the serve stream so tracebacks render with and without `-v`. Without it an unexpected worker exception would leave one message line in `docker logs` and nothing else, recoverable only by restarting with `-v`. Pinned by two tests |
| T-31-20 | Tampering | one-shot CLI logging contract | mitigate | The new parameters are keyword-only with defaults that preserve today's behaviour, and `test_one_shot_command_still_attaches_the_file_handler` is the explicit regression guard. Phase 28's exit-code and one-line-message tests must pass unmodified |
</threat_model>
