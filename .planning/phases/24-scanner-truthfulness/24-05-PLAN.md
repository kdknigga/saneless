<objective>
Set the device's options in an order that cannot silently invalidate itself, read the resolution back
from the device, and make the last ad-hoc source comparison in the scanner layer consult the single
classifier.

Purpose: SANE backends clamp or snap resolution and report it — measured, `dev.resolution = 5000`
returned `1200.0` and `0` returned `1.0`. Today options are set mode → resolution → source, so a
source change can reload descriptors and clamp the earlier values (M-16). And
`sane_backend.py:495`'s `effective_source == "Auto"` is case- and whitespace-sensitive: a device
reporting its source as lowercase `auto` classifies as `AUTO`, takes the single-page path, and
**skips the override entirely**, so `auto_source_mode = "adf"` is silently ignored and a stack
returns one page. That is the exact user-visible failure C-06 exists to eliminate, surviving in a
second place.

Output: `scan_pages` split for branch headroom, options set source-first with the resolution read
back, the `SaneDevice` Protocol's `resolution` type corrected, the Auto override routed through
`classify_source`, and D-01 recorded as settled in `base.py`.
</objective>

Measured resolution behaviour on real `test:0` (RESEARCH.md § Finding 9):

| Requested | Read back |
|---|---|
| 5000 | `1200.0` |
| 300 | `300.0` |
| 0 | `1.0` |
| 150 | `150.0` |

The return type is **`float`**, so `int(dev.resolution)` is required. `SaneDevice` at
`sane_backend.py:219` declares `resolution: int`, which is a type lie.

Why source-first ordering matters, from `.venv/lib/python3.14/site-packages/sane.py:188-213`:

```python
    result = d['dev'].set_option(opt.index, value)
    if result & _sane.INFO_RELOAD_OPTIONS:
        self.__load_option_dict()   # a source change can reload every descriptor
```

**Measured caveat (A5):** on `test:0`, setting `source` after `resolution` did **not** clamp the
resolution — 1200.0 survived. The ordering change is still correct, because feeders commonly have a
different ceiling, but `test:0` **will not demonstrate the bug**. This needs a fake-based test: a
`FakeSaneDev` whose `source` assignment narrows the resolution constraint. Do not try to prove it
against the real backend.

The measured case-sensitivity defect (RESEARCH.md § Finding 6):

| Source string | `== "Auto"` | `classify_source` |
|---|---|---|
| `"Auto"` | True | `AUTO` |
| `"auto"` | **False** | `AUTO` |
| `" AUTO "` | **False** | `AUTO` |
| `"Automatic Document Feeder"` | False | `FEEDER` |
