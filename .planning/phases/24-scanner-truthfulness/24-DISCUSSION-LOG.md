## Unknown-source routing

| Option | Description | Selected |
|--------|-------------|----------|
| Safer default (Recommended) | C-06's proposal: if the device exposes a `source` option and the name is not the flatbed entry, take the multi-page path. Bounded downside — `multi_scan()` on a flatbed yields one page | |
| Keep single-page | Status quo (`base.py:97-101`). Only names matching an explicit rule feed | ✓ |
| Only if feeder exists | Route UNKNOWN multi-page only when the device's source list also contains a FEEDER/FEEDER_DUPLEX entry | |

**User's choice:** Keep single-page.
**Notes:** Diverges from the recommendation. Phase 21's D-11 had deferred this exact bet to
Phase 24, so the answer closes it permanently rather than deferring a third time. Roadmap
criterion 1 is unaffected — "Automatic Document Feeder" classifies FEEDER on the
`"document feeder"` token, never reaching UNKNOWN.

## Blank-page policy move

| Option | Description | Selected |
|--------|-------------|----------|
| Raise, never drop (Recommended) | Any integrity failure aborts the scan; makes "the backend drops no pages" true by construction | |
| Skip but report the count | Keep `continue`, surface the dropped count | |
| Skip, raise only if all fail | M-14's literal prescription: skip individually, raise only when every fed page was rejected | ✓ |

**User's choice:** Skip, raise only if all fail.
**Notes:** Two follow-ups were generated by this choice — the visibility of the skipped count,
and manual-duplex parity. Both are logged below.

### Follow-up: skip-count visibility

| Option | Description | Selected |
|--------|-------------|----------|
| Log only (Recommended) | WARNING per skip; no count crosses the generator boundary; leave plumbing to Phase 29's HARD-01 | |
| Surface the count now | Give the backend a way to report pages rejected for integrity | ✓ |
| Fold into pages_removed | Add to the existing field | |

**User's choice:** Surface the count now.
**Notes:** Diverges from the recommendation, which cited the risk of pre-empting Phase 29's
ordered page-record design. Accepted with the mitigation that the carrier object stays minimal.
Folding into `pages_removed` was rejected because Phase 30's APPL-03 renders that field as
"pages removed as blank".

### Follow-up: manual-duplex parity

| Option | Description | Selected |
|--------|-------------|----------|
| Accept, document it (Recommended) | A corrupt page genuinely means the passes no longer correspond; the mismatch path reports it honestly | ✓ |
| Raise during duplex only | Backend raises on integrity failure only mid-duplex | |
| Reconsider: raise always | Revert to raising on any integrity failure | |

**User's choice:** Accept, document it.
**Notes:** Recorded explicitly so a verifier does not read SCNR-03's "manual-duplex page parity
survives" as forbidding it. The "raise during duplex only" option would have required the
backend to know it is mid-duplex, which is Phase 25's DPLX-01.

## Feeder slug collisions

| Option | Description | Selected |
|--------|-------------|----------|
| First keeps adf-simplex (Recommended) | First/only feeder keeps the name; additional colliding feeders slug from their source names | |
| Always slugify feeders | Every FEEDER slugs from its own name; collisions impossible by construction | ✓ |
| Keep first, warn | First feeder wins; later collisions logged and skipped | |

**User's choice:** Always slugify feeders — extended on the follow-up to all four SourceKinds.
**Notes:** Diverges from the recommendation. Discovered while working the consequence: `_slugify`
only replaces spaces and underscores, so Canon's `"ADF (left aligned)"` would emit
`adf-(left-aligned)` — not a legal TOML bare key. Three follow-ups resulted.

### Follow-up: `_slugify` hardening

| Option | Description | Selected |
|--------|-------------|----------|
| Strict charset (Recommended) | Restrict to `[a-z0-9-]`, collapse runs, trim, guard the empty result | ✓ |
| Keep permissive, quote keys | Leave `_slugify` alone and quote non-bare TOML keys | |
| Share Phase 23's sanitiser | One character-set helper under both the filename and slug rules | |

**User's choice:** Strict charset.
**Notes:** The shared-sanitiser option was flagged as partly re-opening Phase 23's D-19, which
deliberately separated the two rules.

### Follow-up: scope of "always slugify"

| Option | Description | Selected |
|--------|-------------|----------|
| Slugify both (Recommended) | FEEDER and FEEDER_DUPLEX slugify; FLATBED and AUTO keep friendly names | |
| Simplex only | Keep `adf-duplex` hard-mapped | |
| Slugify everything | All four SourceKinds slug from the device's own wording | ✓ |

**User's choice:** Slugify everything.
**Notes:** Chosen knowing `auto-scan` is documented at
`docs/how-to/configure-scan-profiles.md:91` and `docs/reference/configuration.md:127`. Those
sentences are corrected in-phase.

### Follow-up: orphaned profiles

| Option | Description | Selected |
|--------|-------------|----------|
| Prune in this phase (Recommended) | Remove `auto_generated = true` profiles absent from the fresh set; never touch unflagged ones | ✓ |
| Warn, don't delete | List stale names and let the user remove them | |
| Leave it to Phase 27 | Let CFG-07 handle merge semantics | |

**User's choice:** Prune in this phase.
**Notes:** Mapped against the user's own live `saneless.toml` during discussion: `[profiles.auto]`
is unchanged, `[profiles.default]` is untouched (no `auto_generated` key), and `adf-simplex` and
`flatbed-scan` are pruned in favour of `adf` and `flatbed`. Without the prune the user would
hold six profiles, two stale.

## Geometry units + presence

| Option | Description | Selected |
|--------|-------------|----------|
| Presence + unit convert (Recommended) | Check all four options exist; read the unit at index 5; MM direct, PIXEL via read-back; else crop | ✓ (extended) |
| Presence + MM only | Use geometry only when the unit is MM | |
| Also validate the range | Additionally check the requested area against the br-x/br-y constraint | |

**User's choice:** Presence + unit convert — with the request to "also accept cm and inches".
**Notes:** Verified against `_sane` directly that SANE has no `UNIT_CM` and no `UNIT_INCH`; the
complete set is NONE/PIXEL/BIT/MM/DPI/PERCENT/MICROSECOND. Put back to the user, who then chose
the total-enum form for the SANE side and agreed the user-facing cm/inch capability should
become its own new phase.

### Follow-up: unit handling form

| Option | Description | Selected |
|--------|-------------|----------|
| Total enum + assert_never (Recommended) | `GeometryUnit` over all seven codes with `match` + `assert_never` | ✓ |
| Just MM and PIXEL | Plain branching with a fall-through | |
| Also accept cm/inch from config | User-facing scan area in cm or inches | ✓ (deferred to its own phase) |

**User's choice:** Total enum + assert_never, **and** cm/inch as a separate future phase.
**Notes:** The enum form follows Phase 21's D-08, which measured that only `match` +
`assert_never` is enforced by both `ty` and `pyrefly`.

## Read-back DPI reach

| Option | Description | Selected |
|--------|-------------|----------|
| One backend result object (Recommended) | One minimal object carries actual DPI and the integrity-skip count; pipeline passes actual DPI to crop and `assemble_pdf` | ✓ |
| Stamp DPI on the images | Write read-back DPI into each PIL image's `.info['dpi']` | |
| Crop only, PDF keeps profile | Backend crops with actual DPI; `assemble_pdf` keeps `profile.resolution` | |

**User's choice:** One backend result object.
**Notes:** Chosen partly because it gives the already-accepted skip count (above) a home without
inventing a second channel. The `.info['dpi']` option was rejected on Phase 23's measured
evidence that the field is empty on this path and that a PNG round-trip degrades 300 to
299.9994. `pdf.py:156` already names this phase as the one that changes the `dpi` argument.
