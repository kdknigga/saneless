The two duplicated parsing blocks being replaced. **Copy 1**, `sane_backend.py:323-335` inside
`get_capabilities`:

```python
            for opt in raw_options:
                if len(opt) < 9:
                    continue
                name = opt[1]
                constraint = opt[8]
                if name == "source" and isinstance(constraint, list):
                    sources = [str(s) for s in constraint]
                elif name == "resolution" and isinstance(constraint, list):
                    resolutions = [int(r) for r in constraint]

```

**Copy 2**, `sane_backend.py:460-466` inside `scan_pages` (now inside `_resolve_source` after plan
24-05's split) — note it `break`s on the first `source` option and uses `len(opt) >= 9`:

```python
            for opt in raw_options:
                if len(opt) >= 9 and opt[1] == "source":
```

**Critical difference the helper must preserve:** copy 2 sets `has_source_option = True` on option
**presence**, independently of the constraint shape, and the source-validation branch depends on it.
A `_constraint()` that returns only the parsed constraint loses that distinction. The helper must
report presence and constraint separately, or the caller keeps its own presence test.

Measured against real `test:0` (RESEARCH.md § Finding 4):

```
SOURCES: ['Flatbed', 'Automatic Document Feeder']   RESOLUTIONS: []
```

Its resolution constraint is `(1.0, 1200.0, 1.0)` — **float** members, which matters for the field's
type.

The field being extended, `src/saneless/scanner/base.py:114-121`:

```python
@dataclass
class DeviceCapabilities:
    sources: list[str]
    resolutions: list[int]
    modes: list[str]

```

prints blank on a range-reporting device, and the `if caps.raw_options:` guard at `:219` is the analog
for conditionally rendering whichever field is populated.

The consumer that silently falls back, `auto_profiles.py:100-102`:
