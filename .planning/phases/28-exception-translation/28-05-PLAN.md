<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| SANE device / network backend -> saneless | Device names, option values and library error strings come from hardware or a network scanner host |
| ScanError text -> terminal, job.error, web UI | Wrapped messages are printed and rendered |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-28-15 | Tampering (terminal escape) | option values and device names in one-line messages | mitigate | Option values rendered with `!r` (escapes control characters); the web layer autoescapes `job.error`; device names come from SANE enumeration or the operator's own config |
| T-28-16 | Denial of service (masking) | `dev.close()` raising in `finally` | mitigate | Close failure logged with `exc_info` and not re-raised, so the scan's real error propagates; test pins it |
| T-28-17 | Information disclosure | install-hint message | accept | Contains only the ImportError text (a module or shared-object name) |
| T-28-18 | Elevation / hardware safety | tests opening the real scanner visible on the dev host | mitigate | All new tests use FakeSaneModule via `_backend_with` / monkeypatch; no `sane_hardware` marker added |
</threat_model>
