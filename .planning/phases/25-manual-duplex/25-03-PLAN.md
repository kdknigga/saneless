<objective>
Replace `PipelineRequest.flip_event` + `abort_event` with one `FlipCoordinator` ABC returning one
total `FlipOutcome`, and make the flip wait bounded.

Purpose: DPLX-04's contract and DPLX-05's timeout. Today `abort_flip()` sets *both* events so the
waiter wakes and then separately inspects `abort_event` — that wake-then-ask-why two-step is where
M-02's dead Abort lives, and `request.flip_event.wait()` with no timeout is M-07's parked worker
thread. One atomic answer removes both at the root.

Output: `FlipOutcome`, the `FlipCoordinator` ABC, `WorkerFlipCoordinator`, a bounded and
`match`-dispatched wait inside `_scan_manual_duplex`, and every duplex test migrated onto the seam.
</objective>

**Wave 0 enabler carried by this plan:** `tests/conftest.py` needs a concrete always-continue
`FlipCoordinator` subclass. About ten migrated pipeline tests depend on it and it must land in the
**same commit** as the `PipelineRequest` field swap, because the swap is what breaks them.

**Two lint traps that are real failures, not style notes:**

1. **`PLR0913`.** `_scan_manual_duplex` has exactly five parameters and ruff's default `max-args` is
   five (executed: `6 > 5` errors). `pyproject.toml` sets no override, and CLAUDE.md forbids both
   raising the limit and `# noqa`. `_handle_duplex_mismatch` is also at five — **do not add a
   parameter to it either.**
2. **`S101`.** `assert` is selected project-wide and relaxed **only** for `tests/**`
   (`pyproject.toml:91` vs `:130`). RESEARCH.md's own `WorkerFlipCoordinator` sketch ends in a bare
   `assert answer is not None` — **copying that into `src/` is a lint failure.** Structure `_resolve`
   to *return* the claimed outcome so the type narrows by return value, with no assertion.

**Planner discretion recorded — `_FlipContext` instead of a bare `timeout` parameter.** RESEARCH
recommends dropping `notify` and spending the freed slot on `timeout: float`. That frees the slot but
leaves a second problem: `PipelineRequest.flip_coordinator` stays `FlipCoordinator | None` (simplex
profiles legitimately have none), so inside `_scan_manual_duplex` the type checkers still see an
Optional, and narrowing it there needs either a bare `assert` (banned by `S101`) or a raise that
duplicates plan 25-04's guard. Instead, pass a small frozen dataclass `_FlipContext(coordinator:
FlipCoordinator, timeout: float)` as the fifth parameter. `notify` is still derived, the argument
count is still five, and `coordinator` is **non-Optional at the callee**, so the None-narrowing
happens exactly once at the call site. This uses the in-tree `_DeliveryContext` precedent
(`pipeline.py:388-412`), a frozen dataclass whose docstring names `PLR0913` as the reason it exists.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| unauthenticated LAN POST → worker coordinator | `/api/flip/continue` and `/api/flip/abort` reach `signal_continue` / `signal_abort` with no authentication |
| wall clock → worker thread | The timeout decides how long the single worker thread may be held |
| operator config → timeout value | `output.flip_timeout_seconds` bounds the wait |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-25-09 | Denial of Service | unbounded flip wait parking the single worker thread | mitigate | `wait_for_flip(timeout)` is now the only wait, bounded by `flip_timeout_seconds` (default 600). This closes M-07 — today one forgotten browser tab hangs the appliance until restart. **This plan is itself the DoS mitigation and is the phase's net-positive security change** |
| T-25-10 | Tampering (race) | two concurrent signals to one coordinator | mitigate | `_resolve` claims the single answer under a `threading.Lock` and the outcome is written **before** the event is set. A late or losing signal is dropped and the first answer stands (D-16). Race-free by construction rather than by timing |
| T-25-11 | Tampering | unauthenticated cross-site POST aborts a stranger's in-progress scan | accept (deferred) | ASVS V4 applies but **ROBU-10 / N-22 (Phase 26)** owns `Sec-Fetch-Site` rejection, and APPL-09 (Phase 30) owns the owner-only prompt. The trusted-LAN posture is a recorded product decision (`REQUIREMENTS.md:218`), not an oversight. Recorded here as a known, accepted, deferred exposure — the verifier must not fail this phase for its absence |
| T-25-12 | Denial of Service (self-inflicted) | `flip_timeout_seconds = 0` | accept | Operator-owned config; `0` is deliberately useful as the 4 µs test seam |
| T-25-13 | Repudiation | an aborted job indistinguishable from a scanner failure | accept (deferred) | D-15 stops at a clear `ScanError` message naming the flip prompt. Classifying it as cancelled is **Phase 28's EXC-04/N-08**; implementing it here would leave EXC-04 split across two phases |
| T-25-SC | Tampering | package installs | N/A | This phase installs nothing |
