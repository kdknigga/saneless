Implemented behaviour to describe (plans 27-01..27-07):
- Error shape: `Configuration error in <file>:` then one line per problem, e.g. `[paperless] unknown key 'tokne' (did you mean 'token'?); valid keys: url, token, consume_dir`, `[paperless] unknown key 'web_port'; it belongs in [output]`, `environment variable 'SANELESS_SCANNER__HOSTNAME': unknown key 'hostname' in [scanner] ...`; values are never printed; exit 2
- Unknown `SANELESS_*` first segment (e.g. `SANELESS_PAPERLES__TOKEN`, `SANELESS_CONFIG_PATH`, `SANELESS_OUTPUT_WEB_PORT`) -> rejected with a suggestion, exit 2
- `--config PATH` missing or not a regular file -> exit 2 naming the path; a directory at a search path is skipped
- `-v`: saneless loggers at DEBUG, mirrored to stderr; root/library loggers and uvicorn keep `log_level`
- Startup INFO line: `Configuration: <path or "no config file; defaults + environment">; from environment: <dotted names>`
- `--help` on any subcommand needs no valid config
- Title rule: typed title, else profile `title`, else `Scan <YYYY-MM-DD HH:MM>` (UTC)
- auto-profiles grouped output and merge semantics, EBUSY message and exit 2, new file mode 0600 (see 27-04/27-05 SUMMARY and docs/how-to/configure-scan-profiles.md as edited by 27-05 -- link to it rather than repeating it at length)
