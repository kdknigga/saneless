<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| environment (HOME, XDG_*) -> path resolution | Ambient variables decide where config is read and state is written |
| config values -> filesystem paths | Operator-supplied path strings become directories the process creates and writes |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-25 | Tampering | relative `$XDG_CONFIG_HOME` / `$XDG_STATE_HOME` making discovery cwd-dependent | mitigate | relative or empty values ignored per the basedir spec; tests for both |
| T-27-26 | Tampering | unintended variable expansion in path settings (`$VAR`) | mitigate | only `expanduser` is applied; test asserts `$HOME/x` stays literal |
| T-27-27 | Elevation | XDG variables pointing discovery at an attacker-controlled config | accept | the environment is controlled by the operator who launches saneless; `/etc/saneless` and `./saneless.toml` already have the same trust level; D-13 still rejects unknown SANELESS_* names |
| T-27-28 | Denial of service | late permission failure mid-scan for a deep missing directory | mitigate | nearest-existing-ancestor writability check at startup (M-20) |
</threat_model>
