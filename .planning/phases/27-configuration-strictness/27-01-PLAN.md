<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| config file / environment -> Settings | Operator-controlled values, including the Paperless token, enter pydantic models |
| browser form -> POST /api/scan | Untrusted typed title combined with a profile title |
| Settings -> logs, reprs, tracebacks | Any place a settings object is formatted can disclose the token |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-token | Information disclosure | `PaperlessConfig.token`, `repr(settings)`, `model_dump` | mitigate | `SecretStr` field; `get_secret_value()` only in `cli.py scan` and `web/app.py`; test asserts the token is absent from `repr` and JSON dump |
| T-27-01 | Tampering | `ProfileConfig.default_title` -> job title | mitigate | `max_length=TITLE_MAX_LENGTH` on the profile field, so a profile title cannot exceed the ROBU-08 bound that `Form(max_length=...)` enforces only on typed titles |
| T-27-02 | Tampering / DoS | `OutputConfig.log_level` | mitigate | `Literal` plus before-validator; unknown names fail at load instead of crashing `getattr(logging, ...)` later |
| T-27-03 | Information disclosure | unwrapped token inside `PaperlessClient` | accept | Already a plain `str` in the client before this phase; the client builds only the Authorization header (paperless.py:215) and never logs it |
| T-27-04 | Tampering (race) | `start_scan` profile check then read | mitigate | single `worker.get_profile` call under `_profiles_lock` replaces `has_profile` + later read |
</threat_model>
