New contract this plan creates (consumed by plan 27-04):
- `replace_file_atomically(path: Path, text: str) -> Path` in module `saneless.atomic_write`, `__all__ = ["replace_file_atomically"]`
  - Returns the real file that was replaced (`path.resolve()`); differs from `path` for a symlink
  - Raises `ConfigError` for EBUSY; `PermissionError` for an unwritable existing target; any other `OSError` unchanged

Existing analog, src/saneless/paperless.py `_deliver_to_consume_dir` (lines 331-383): stage file, write, flush, `os.fsync(fileno)`, `staged.replace(dest)`, `except OSError: staged.unlink(missing_ok=True); raise`. Its docstring explains why `Path.replace` is used instead of `os.replace` (ruff PTH105, no per-line suppression allowed).

From src/saneless/exceptions.py: `class ConfigError` (line 23).

Verified primitives (RESEARCH § Pattern 4, kernel 5.14): mkstemp creates 0o600 with O_EXCL; rename onto a single-file bind mount gives OSError errno EBUSY, onto a file inside a directory bind mount succeeds; non-root `os.fchown(fd, own_uid, own_gid)` succeeds and `os.fchown(fd, 0, 0)` raises PermissionError; `Path.resolve()` + replace keeps a symlink working; `os.open(dir, os.O_RDONLY | os.O_DIRECTORY)` + `os.fsync` works locally.

House lint rules (PATTERNS S-1, S-2): `msg = ...; raise ConfigError(msg) from exc`; `tmp.replace(target)` never `os.replace`; `target.stat()` never `os.stat`; `os.fchmod`, `os.fchown`, `os.fsync`, `os.open`, `os.access` are allowed. Tests patch `pathlib.Path.replace` via `monkeypatch.setattr(Path, "replace", fake)`.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| saneless process (root in container) -> host-mounted config directory | A privileged writer replaces an operator-owned file |
| temp file during the write window | Content (may include the token) exists in a second file briefly |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-27-write | Denial of service (corrupt config) | `replace_file_atomically` | mitigate | mkstemp in the target directory, fsync file, `Path.replace`, best-effort directory fsync; temp unlinked in `finally` on every failure |
| T-27-05 | Information disclosure | temp file permissions | mitigate | mkstemp creates 0600; the original's mode is applied only after contents are written, just before rename, never wider than the file already was |
| T-27-06 | Tampering / Elevation | predictable temp name / planted symlink | mitigate | `tempfile.mkstemp` random name with O_EXCL, never a fixed `.tmp` suffix |
| T-27-07 | Tampering / Elevation | symlink at the config path redirecting a root write | accept | No regression: `write_text` already followed symlinks; path and directory are operator-controlled; the resolved target is returned so the caller logs link and target (D-07, plan 27-04) |
| T-27-08 | Tampering | read-only config silently replaced because rename ignores file mode | mitigate | `os.access(target, os.W_OK)` pre-check raises PermissionError before creating the temp file |
| T-27-09 | Repudiation / usability | ownership flips to root after a container rewrite | mitigate | `os.fchown` to original uid/gid before `os.fchmod`, PermissionError suppressed (D-06) |
</threat_model>
