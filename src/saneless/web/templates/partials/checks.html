{# The status strip's swap target, and two load-bearing facts about it. 1. The poll trigger is emitted ONLY while the poll is wanted. A cold cache has no results, so this body asks for itself again every 2s; the body that replaces it has results, carries no trigger, and so ends the poll. That is the in-tree idiom (partials/status.html lines 1-6) and it is deliberately NOT HTTP 286, which would need a change to the tuned htmx-config meta in base.html. 2. There is never a steady-state poll. Once results land the strip is refetched only by Check again, by the terminal-state reload, or by a page load. A permanent poll would keep D-05's lazy refresher awake for every abandoned browser tab, which is the exact cost D-05 exists to avoid. `oob` follows partials/scan_button.html: the one copy of this markup renders itself out-of-band when a scan submit carries it, so the swap target's id is never duplicated by a wrapper around a second copy of this markup. The template owns no vocabulary.
